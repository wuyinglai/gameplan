## §2 世界与移动

### 2.1 每天走几格（移动主式）

```
v  = round( (S − c_侦) / c )        # 日常：只花当天回复的量
v* = round( (S_max − c_侦) / c )    # 冲刺：池攒满（S_max = 2S = 100）
```

> 🔴 **2026-09-30：野外体力改「存量池」（`S_max = 2S`）** —— 与战斗体力**同构**（战斗也是 `上限 = 2 × 每回合回复`）。**"攒"在两边的意义也一样**：**不是变强，是把时间换成距离**（战斗里攒 = 把两回合的量压进一回合集火；野外攒 = 把两天的量押进一天冲刺）。**代价**：野外攒池期间**照常按天消耗补给与工资**（那两笔才是硬账），所以**冲刺永远不是免费的**。
> 🔴 **`S` 与人数 / 个体无关**：野外是**车队一个池**（车就那么多，人再多也不会走得更快，只会更费补给）—— **别把战斗的 `S = Σ 各人体力` 搬过来**。

**三个设计理由**（为什么是这个形状）：

| 形状 | 理由 |
|:--|:--|
| **先减侦察再除** | 侦察是"看清路"的前置动作，**先扣掉才不会出现"侦察完就走不动"** |
| **除法，不是加法** | 能量与消耗是「**总量 ÷ 单价**」的商品关系 —— 这正是不停车/换车轮能"多挤出格"的数学基础 |
| **取整（round）** | 格是整数，走不了半格 → **余数天然浪费掉**，于是"每格再省一点"就能跨过整数关口多走一格（升级手感的来源） |

> 🔴 **2026-10-05：取整这一条已不再服务于"车轮升级"**（车轮不再是提速档）。`round` 的余数浪费现在只来自**玩家自己选择花不花体力** —— 这仍然是可感知的决策（"再攒一天"vs"多走半格"）。

### 2.2 ~~两个旋钮：加能量 / 降消耗~~ → **只留「加能量」**（2026-10-05 用户裁定 · 原整节作废）

🔴 **原节内容**：把速度做成两个轴 —— **加能量**（动力：驼兽 / 旧文明引擎，抬高 `S`）与 **降消耗**（车轮：改良 / 精制，压低 `c`）。**现整节作废。**

**删掉「降消耗」轴的理由**：只要允许 `c` 下降，就开了**越走越快 → 天数反而变少 → 后期被无限拉长**的口子（用户裁定原话）。每日硬账里**吃喝 + 工资占 91%**（`04 §0.3`），这两笔**按"天"计** —— 一旦速度能提升，远征的重量立刻守不住。**速度恒定 = 天数恒定 = 成本恒定。**

**现在只有一个装备旋钮：加能量（`S`）**

| 方向 | 谁提供 | 改哪个符号 | 后果 |
|:--|:--|:--|:--|
| **加能量**（唯一装备轴） | **动力装置**（旧文明引擎 / 改装动力） | 抬高 `S`（池上限 `S_max = 2S` 同步） | 一天的总劲变大 → 格数变多 |
| **降消耗** | ~~车轮~~ | ~~压低 `c`~~ | 🔴 **不存在** —— `c` 恒为 20 |
| **攒池**（不是装备，是节奏） | 玩家自己少花 | 用掉 `S_max` 那一半 | 前几天少走 → 一天冲 5 格 |

> 🔴 **术语（2026-10-09 用户裁定）**：动力装置**统一叫「动力装置」** —— 旧稿写「**驼兽 / 旧文明引擎**」，其中**"驼兽"已删除**。
> **为什么删**：驼兽本质是**牲畜**，而牲畜系统**不做**（`第3A类 §4.5.4`：**只作背景，不做系统**）—— 留着"驼兽"这个词会让人以为**牲畜能抬`S`**，等于凭空多出一条提速轴，直接违反「速度恒定」。**动力装置 = 机器，不是牲口。**
> ⚠️ **这不等于"删掉了选择"** —— 选择从**装备轴**搬到了**节奏轴**：*"今天花不花这10 点侦察 / 采不采这一趟"*、*"攒一天冲 5 格还是稳走 2.5 格"*。**唯一消失的是"买更好的轮子 = 走更快"这条无脑升级线。**
> 📌 **口径来源**：2026-09-22 用户裁定「不要全部都是降消耗，或者全部都是加能量」→ 🔴 **2026-10-05 用户裁定「车轮改每格消耗删掉，否则后期无限拉长」** —— **后者覆盖前者的前半**。**降消耗轴作废，只保留加能量 + 攒池。**
> ⚠️ **配套代价（不变）**：**动力装置占车厢格 + 耗油**（油走"按格"消耗，见 §5.4）。
> 🔴 **2026-10-09**：旧稿这句还写着「**驼兽沿途自采、不耗粮**」—— **已删**。驼兽属牲畜、牲畜系统不做（`第3A类 §4.5.4`），**只有动力装置占格耗油**这一条成本。

### 2.3 野外动作的耗点关系（规则）

一天的能量 `S` 是一个**预算**，玩家自己分配：

```
走 1 格 = c   ｜   侦察 1 次 = c_侦   ｜   采集 / 休整 1 次 = c_事
```

- `c_侦`、`c_事` **固定**，不随路况变 —— **情报与"歇一口气"的价值不该跟着天气打折**；
- `c_事` 取与侦察同价：**"做一件事" ≈ "换一格路"**，这条等值让玩家在"赶路 / 干活"之间有一个干净的取舍；
- **"标准打法"的定义**：预先留出一次侦察的预算，剩下的走格 —— `v` 就是按这个口径算的。

### 2.4 车辆：从哪来、怎么分工

```
车队 = 货车（载货 · 计耐久） + 单车（载人 · 不计耐久 · 不载货）
```

| 车种 | 干什么 | 为什么这样分 |
|:--|:--|:--|
| **货车** | 货舱的**唯一**来源；有耐久；归零抛锚（需修回阈值才能走） | 把"货"变成可被打击的目标 → 战斗失败会真的伤到生意 |
| **单车** | 载人；**不载货、不计耐久、不被攻击** | 把"人的运载"从战损里摘出来 —— **挨打掉的是货，不是人** |

> 载重与货舱的换算、单车/货车的具体格数：**查 `0A 第6A类 §14` 与锚表**。

### 2.5 扩容与升级（两条路，你点名要的规则）

```
横向扩容 = 加挂货车      →  K 增加，每辆 +q 格 / +耐久上限
纵向升级 = 单车格数提升   →  q 逐级上升（每级格数与**级数上限**由锚表定）
```

| 路 | 改什么 | 被谁闸住 | 为什么必须有这条闸 |
|:--|:--|:--|:--|
| **扩容（加车）** | 车数 `K` | **车数上限**（`04 §0.7.4`） | 车数 = 车夫数 = 人数 → **多加一辆车，等于多养两个人**（见 §3.2），成本自动反弹 |
| **升级（加格）** | 单车格数 `q` | **级数天花板** | 少了它，"车数上限"就不再是闸 —— **车数上限 × 无限格 = 无限货舱** |

**为什么要两条路并存**（这是 `04 §0.7.4` 的结论，不是新设计）：
> 消耗本身**挡不住无限扩容**，必须靠"车"来闸。但闸只卡横向（车数），纵向（格数）会从旁边漏 —— 所以纵向必须配一个**自己的天花板**。

**连带（很重要）**：`q` 不只影响装货，还决定**能走多远** ——

```
可及路程 ∝ q          （载得多 → 补给带得多 → 走得远；见 §2.6）
```

> 也就是说：**"升级车辆"是玩家唯一的"远行能力"旋钮**，车数被上限按着、编制被后勤规则按着 —— 想跑更远，只能升 `q`。

### 2.6 距离与可达

```
总续航   = W0 × (q ÷ q0) × K / (K + P_战 + P_特)     W0 = 基准车满仓续航常数 · q0 = 基准单车格数（均查锚表）
单程可达 = 总续航 ÷ 2                          ← 远征要往返，去 + 回
补给占货舱 ≈ 天数 × 系数 × (1 + (P_战 + P_特) / K)
```

**为什么是这个形状**：

| 项 | 理由 |
|:--|:--|
| `K / (K + P_战 + P_特)` | 战斗与特殊**占位但不拉货** → 每带 1 个，就割掉一份货舱 → **直接换算成距离损失**。这就是"带护卫是要付代价的" |
| `÷ 2` | 远征是**往返**：去程带上全部补给，回程要么带货、要么空跑 → 单程上限约等于总续航的一半 |
| 按**格数**算、不按**天数**算 | 否则装了动力就能摸到世界另一头，**"太远养不起"这条核心张力会崩** |

### 2.7 订单期限

```
期限 = (格数 ÷ 基准速度) × k_期         （k_期 查锚表：短 2.0 / 中 2.1 / 长 2.2 / 超长 2.3）
```

🔴 **`k_期` 不是"缓冲"，是「沿途活动预算」（2026-09-24 用户定）**：**"订单只规划路线"** —— 订单给的是**起点 + 终点 + 保底报酬**，**怎么走是玩家自己的事**（可以绕弧线、进遗迹待十天二十天）。
**余量 = 期限 − 路程天数**（短 60 / 中 110 / 长 180 / 超长 325 天），**给的是"路上能干什么"**：探索遗迹 / 跑村庄卖货 / 接顺路单 / 分段推进。
**代价自成天平**：**早交 = 省消耗但少收获；绕路 = 多消耗但多收获** —— 玩家自己押风险。**迟到仍 ≠ 失败**（铁律 7）。
🔴 **为什么比 1.3 宽得多**：1.3 只够"绕一下"，撑不起沿途玩法。**期限余量的成本不由期限承担、由硬账承担** —— 多待一天多烧一天硬账（后期 1,493 金/天）→ **给宽不会让游戏变简单，只多开一个选项**。

### 2.8 灰度（**三层叠加** · 2026-09-29 用户定）

```
显示灰度 = 夹( L1 + L2 + L3 , 0 , 1000 )

L1 区域灰度 = Σ(w_i × G_i) / Σ(w_i)    w_i = 1 / d_i²   （G_i = 第 i 个地点锚点的灰度 · d_i = 到该地点的距离）
L2 随机灰度 = L1 × r ,  r ∈ [−20%, +20%]，且 |L2| ≤ 40   （每 3 天重掷一次）
L3 天气灰度 = 灰烬风 +100 · 灰烬风暴 +200 · 其余天气 0       （随天气段，天气段结束即消失）

🔴 预算约束（先于上面三式成立 · 保证"夹"永不触发）：
   满格 1000 = L1 上限 750 + L2 封顶 40 + L3 风暴 200 = 990
```

| 项 | 理由 |
|:--|:--|
| `L1` 用**反距离加权插值**，不用硬分区 | 灰度是**连续场** → **相邻两片区域必然接近**、中间有过渡。硬分区会造出"隔一格跳 50"的假边界，与 `04 §0.5.3`「**相近的两条路灰度 ≈ 一致**」直接冲突 |
| `L2` 用**百分比 + 封顶** | ① 低灰区（`L1 = 200`）只摆 **±40** 以内 → 稳定可预期；② 高灰区（`L1 = 750`）**不会摆到 ±150**（封顶 **40**）→ **不轻易跨越阈值带**，区域的"性格"仍然可预判；③ **`L1` 越高，绝对波动被 `±40` 压得越紧 → 深处反而更稳、更可预判**（这是想要的：**越深越可怕，但越可预期**）。⚠️ **封顶 40 不是拍的** —— 由**预算倒推**：`1000 − L1 上限 750 − 风暴 200 = 50`，取 **40** 留 10 点缓冲 |
| `L3` 只认**灰烬系天气** | L3 是"灰烬生态专属"的临时加值。普通雨天 / 高温 / 大雾**不加灰度**（那些是第 5A 类自己的效果，**别串台**） |
| **刻度为什么用 1000 制** | 🔴 **「量级即语言」** —— 灰度是**世界尺度**（环境压力），天生比**身体尺度**（血量 `A13` · 装具盘 `A21` 的 **100 制**）**大一个量级**：读数 **870** 一眼就是"待不住了"，**87 只是个"像数值的数值"**。**1000 制下档距天然取整**（100 / 150 / 200）→ **不必引入小数点**、后期加档**不用动刻度**。🔴 **"满格必须能被摸到"的兑现方式 = 预算制**：把 `L1` 上限压到 **750**，让 **`750 + 40 + 200 = 990`** 把最深灰区推到**接近满格** —— **满格是留给"最坏叠加"的位置，不是留给某块地图的常驻属性**。✅ **附带好处**：**没有任何区域"已顶格"** → L2 / L3 对任何地方仍然生效（"最灰的地方不会更灰"这个问题**不复存在**） |
| **`L1` 量程为什么是 `0 ~ 1000`、而上限只用到 750** | ① **量程 0~1000**：与**显示灰度同一把尺子**，换算直白、加档不改刻度；② **上限只到 750**：把 **250** 留给 `L2 + L3` → **由预算保证永远不超 1000**（`夹` 只兜底）；③ **实际最低区域 ≈ 200**（前期带）—— "灰烬是世界底色"靠**分布**表达，不靠刻度下界 |

🔴 **只有 `L1` 决定资源构成** —— `L2` / `L3` 只改"**当下多危险**"，**不改"这一带产什么"**（`0A 第8A类 §2` 铁律 1）。
🔴 **本文件只写等式，不写各区域的具体灰度值** —— 锚点值随**地图生成**时分配（`12` 重做时落地），**参数唯一来源 = `04 §0.1` A23**。

### 2.9 事件触发（**外部四层抽取 + 内部三重闸门** · 2026-09-29）

```
【外部事件】四层抽取（0A 第5A类 §3.1 / §3.3）
    P(强事件)   = f(区域)                                  区域表 · 待随新地图重划
    大类权重    = 区域基准权重 × 地点覆盖乘数                9 大类
    小类权重    = 大类内分布（合计 1）                       35 小类
    条目权重    = 小类内分布（合计 1）                       具体条目
    冷却        = 命中后该"大类"权重 × 保留系数              §6.2

【内部事件】三重闸门（0A 第5A类 §5.2）
    闸门1  无任何压力源                       → P = 0（直接跳过）
    闸门2  距上次内部事件 < N 天               → P = 0（直接跳过）
    闸门3  P = 基准频率 × 人数系数 × 压力强度 ，且 P ≤ 每日上限

    压力强度 = Σ(压力源等级 × 该项权重) / Σ(满级 3 × 该项权重)     归一化到 0~1
    人数系数 = f(人数) ，单调递增                                 人越多越高
```

| 项 | 理由 |
|:--|:--|
| 🔴 **人数必须做"乘数"，不能做"加项"** | 加项会让「**人少 + 压力重**」与「**人多 + 压力轻**」算出**同样的概率** → 不符合直觉。乘数才有「**14 人扛得住、50 人扛不住**」的效果（用户：「**人越多触发概率越高**」） |
| 🔴 **必须有「每日上限」** | 无上限时，压力拉满 = **每天必爆** —— 而内部事件**惩罚很重**（直接咬钱 / 货 / 士气）。**上限是"惩罚重"的对冲** |
| 🔴 **总冷却 `N` 与压力大小无关** | 频率上限必须**独立于压力**：否则压力一大，冷却就被绕过，"降频"变成一句空话。设计意图 **N 绝不短于"一周一次"** |
| **闸门 1 用"清单"而不是"阈值高"** | 只要**一条压力源成立**就开门 —— "太累"和"饿"是**身体信号**，出现得比"士气低"更早（用户点名要求它们是**独立扳机**） |
| **外部只冷却到"大类"** | 细到小类会太碎、也难维护；**小类内部的稀有度由权重表承担** |

> ⚠️ **以上 4 个系数（基准频率 / 人数系数曲线 / 压力强度权重 / 每日上限）+ `N` 的取值 = `24_数值计算器.html` 试定后回填** —— 本文件**只写等式与理由，不记求值结果**（工序铁律）。
> ⚠️ **不新增锚**（用户未定具体值）→ 在 `04 §15.2` 登记为 **K10「内部事件参数」= 待定**。

## §3 编制与人力

### 3.1 三条铁律（推导的起点）

```
① 车夫   = K                              （硬 · 跟着车走）
② 后勤   = 车夫 + 战斗 + 特殊               （硬）
③ 总人数 = 2 × (车夫 + 战斗 + 特殊)
```

🔴 **只有 ① 是"硬数"，② ③ 是"跟着算"。** 三个岗里的自由度完全不同：

| 岗 | 谁定 | 规则 |
|:--|:--|:--|
| **车夫** | **车数**决定 | `P_车 = K`，**恒等**，没有第二解 |
| **战斗** | **玩家**定 | "够打这一趟的仗" —— 软 |
| **特殊** | **玩家**定 | "按需招" —— 软 |

> ⚠️ **2026-09-22 用户纠正：特殊人员"有多少个岗位"是玩家自己定的，从来没有固定数。**
> **本文件与任何编制表里都不许再出现"特殊 = N"这种固定配额。** 凡见到写死的"后期 5 个特殊"之类，一律视为**某一套示例编成**，不是规则 —— 换一套车数，它就变了。
> 同理，**总人数也不是"选"出来的**：玩家点车数 + 战斗 + 特殊，总人数由 ③ 自动给出。所谓"前期 14 / 中期 30 / 后期 60"只是三套**示例对应**，不是需要遵守的档位。

### 3.2 推导方向：**车 → 车夫 → 总人数**（单向，不可反推）

| 步 | 关系 | 为什么是这条 |
|:--|:--|:--|
| 1 | **车夫 = 车数** | 一辆车必须一个人开（物理约束）。**"多少车夫"和"多少辆车"是同一个数** —— 用户问的"车夫多少人之后会有多少辆车"，答案就是恒等 |
| 2 | **后勤 = 占编人数之和** | 每个"开车 / 战斗 / 干专业活"的人，背后都要配一个后勤（做饭、修车、装卸、照料） → **1 : 1** |
| 3 | **总人数 = 2 × 占编人数** | 上一条的直接推论 |

🔴 **方向和数量同等重要**：**不能从"我想带多少人"出发**。想多带一辆车 ⇒ 必须先加 **1 个车夫 + 1 个后勤 = 2 人**，工资与补给随之翻上去。

> **为什么这样设计**：任何"堆规模"的冲动，都会**自动带上一倍的后勤成本** → 规模自我设限。这正是"距离即上限 / 管理成本"那套机制的**算式形态**（`04 §0.7.7`）。

### 3.3 工资怎么发

```
日薪总额 = Σ_岗 ( 该岗当前人数 − 初期核心该岗人数 ) × 该岗日薪 d_n
```

| 要点 | 规则 | 理由 |
|:--|:--|:--|
| **四档排序** | 护卫 > 特殊 > 车夫 > 后勤人员 | **按风险与技能定价**：护卫拿命换钱、特殊靠手艺、车夫是常规体力、后勤人员最低 |
| **初期核心不领薪** | 开局那批人**不计入工资** | 🔴 **因为"还没被雇佣"**（用户 2026-10-09 正式解释）：他们跟着商队走是**在等下一次被雇佣的机会**，商队本来就稀少 → 跟着商队是最赚钱最稳当的生路；**雇佣 = 建立关系 = 领工资 + 吃商队的粮**。⚠️ 防死档只是副产品 |
| **用增量、不用全额** | 只算"超出初期核心"的那部分 | **老账不重算** → 以后改锚点，不会连开局的人一起被算进去 |
| **欠薪怎么办** | **只闲置，绝不挖走** | 铁律 7：惩罚只能"**要价**"，不能**剥夺能力** |

> 日薪的具体数额 `d_n` 查锚表；各档岗位人数由 §3.2 推出。

### 3.4 编制为什么能自我约束

三条铁律串起来是一条**单链**：`车数 → 车夫 → 后勤 → 总人数 → 硬账`。改任何一头，全链跟着动（§11 的咬合表）。
**这就是"不用硬限制也能拦住规模"的实现方式** —— 玩家不是被系统禁止带 100 辆车，而是**带不起**（人要翻倍、要吃、要发薪）。

## §4 补给（**两笔账：钱 与 格**）

> **"份"有两面**：**钱 = 份数 × 单价**；**格 = 份数 ÷ 密度**。这两个面**各自有天花板**，必须分开算。

### 4.1 钱

```
食物费/天 = P × 份数 × 粮价(档)        粮价(档) 随包装档升高（§4.3）
水费/天   = P × 份数 × (1 − 路上补水率) × 水价
补给钱/天 = 食物费 + 水费
```

- 份数的基准关系：**1 人 1 天 = 1 份食 + 1 份水**（锚 A7）；
- **水的 `(1 − 补水率)` 是关键**：水能在路上免费获取，粮不能 → 这是"**水便宜、但占地**"的来源。

### 4.2 格

```
食物格/天 = P × 份数 ÷ 密度_食        密度_食 分三档 · 玩家自选（§4.3）
水格/天   = P × 份数 × (1 − 补水率) ÷ 密度_水      密度_水 固定，永不升级（**补水率的定义与反解见 §4.5**）
补给格/天 = 食物格 + 水格
```

**为什么食能升级、水不能**：食是干货，**可以压缩包装**（一份占越来越小的格）；水是液体，**装多少就是多少**。
→ 结果：**水成了吃格大户**（但只花很少的钱）。

> **密度升级的真正作用 = 抵消人数增长**：人数涨几倍，密度也涨几倍 → **每天占舱基本恒定**（≈货舱 25%）。所以"扩编到 3 倍"不会挤压带货空间 —— 这就是「密度可升级」这条设计线的存在理由。

### 4.3 密度是**可选档位**：用钱买空间（2026-09-22 用户定）

食物不是"一种"，而是**三档包装** —— 玩家每次出发自己挑：

```
档位越高：① 每份更贵（钱 ↑）  ② 每格装更多（占格 ↓）

约束：  p₁ < p₂ < p₃   且   d₁ < d₂ < d₃
       单价涨幅 < 密度涨幅      （否则最高档永远不划算 → 没人买 → 这档白设）
```

| | 低档 | 中档 | 高档 |
|:--|:--|:--|:--|
| 每格装几份 `d` | 少 | 中 | **多** |
| 每份单价 `p` | **低** | 中 | 高 |
| 每天**补给钱** | 少 | 中 | **多** |
| 每天**占格** | 多 | 中 | **少** |

**判据（玩家为什么会挑档）**：

```
省下的格 × 该趟每格的收益  >  多花的粮钱        ⇒  才值得上高档
```

- **普通单**：省下的格赚不了几个钱 → **不买高档**；
- **带货特别多的单 / 超长单**：每格收益高 → **高档才划算**。

> 🔴 2026-09-22 用户定：**"价格再提一下，让玩家平时不会选第 3 档"** —— 高档的贵，要**贵到平时肉疼、只有需要腾货舱时才舍得**。
> 🔴 **这条设计的意义**：补给从一个**固定成本**变成**每次出发都要做的取舍** —— 跑什么单、带什么粮，是同一个决策的两面。**"密度升级"不是白给的空间，是花钱买来的。**

### 4.4 为什么非要拆成两笔

| 笔 | 影响 | 天花板 |
|:--|:--|:--|
| **钱** | 利润（进硬账 → 进报价） | 玩家的资金 |
| **格** | **一趟能带多少货**（= 能赚多少） | 货舱总量 |

一笔涨、一笔可能不动（例：粮价涨 → 钱涨、格不变；密度升 → 格降、钱不变）。**混着算就再也分不清该动哪个旋钮。**

### 4.5 水的外部补充（补水率 · 半半天数 · 净水）（2026-09-22 用户定）

**水与粮的根本差别**：**粮只能从城里背，水能沿路补**（中继点 / 城镇 / 野外水源）。所以水那一份要拆成「**自带**」与「**外补**」——**外补的部分不占格**。

#### (1) 三个式子

```
补给占格/天  = P / ρ_食 + (P / ρ_水) × (1 − f)          ← 只有水带 (1−f)，粮不带
半半天数 D   = 货舱 ÷ ( 2 × 补给占格/天 )
反解         f = 1 − ( 货舱 ÷ 2D − P / ρ_食 ) ÷ ( P / ρ_水 )
等效水密度 ρ_水' = ρ_水 ÷ (1 − f)
```

- `f` = **补水率**（= 外补份数 ÷ 全程总需水份数），就是 §4.1 / §4.2 里那个 `(1 − 补水率)`；
- **`D` 为什么叫"半半"**：`补给占货舱 = 单程 ÷ 单程上限` —— **补给占一半 ⇔ 单程走到上限的一半**。这是"一趟舒服的整活"（两头都不憋屈），所以拿它当**档位的标准天数**。

#### (2) 它把「档位解锁」变成结果，而不是禁令

| 判据 | 含义 |
|:--|:--|
| `D_半半 ≥ 该档下限` | 这单**接得到** |
| `D_半半 < 该档下限` | 玩家自己算得出"跑不了" → **不需要写"禁止接单"**（铁律 8） |
| `f` ↑ → `D` ↑ | **净水能力就是射程**：外补多一成，射程往后挪一截 |

#### (3) 净水两档：片（中期）→ 装置（后期）

水**不靠升密度**（`ρ_水` 恒 3），靠**净水手段把野外脏水变成可用水** —— 效果等于**抬高等效水密度**。

```
净水片   1 格 n 片 · 1 片净化 1 格水（ρ_水 份）· 轻、可消耗
净水装置 买断制 · 占 G 格 · 被动补水 · 每日净化量设上限
```

**🔴 两条必须同时成立的硬判据**：

```
① 防套利：  p_片  >  ρ_水 × p_水      ← 1 片换 1 格水 ⇒ 1 片必须比 1 格水贵
② 防印钞：  野外水源由地点/事件按固定频率供给（总量有限）
            且 装置每日净化量 ≤ 该阶段一段补水量 ÷ 30
```

**为什么它是成长项、不是取舍项**：净水手段的**有效密度远高于 `ρ_水`** ⇒ 净赚空间大 ⇒ **玩家没有理由不带**。它和"车升级 / 食升级"是**同一条成长线**；真正的取舍只落在"**带片还是带装置**"这一层，而那由阶段自动决定。

## §5 硬账（"一天到底必须花多少"）

### 5.1 四件套与边界

```
硬账 H = 补给 + 工资 + 车损 + 药包
```

| 进硬账（**必花**） | 不进硬账（**弹性**，有钱才花） |
|:--|:--|
| 补给（吃喝）· 工资 · 车损 · 药包 | 装备 · 招人 · 买车 · 情报 · 火种 |

**为什么划这条线**：报价的**分母只能是"不花就活不下去的钱"**。把装备钱也算进去 → 每次升级装备都会推高报价 → **价格失去锚**，越强越贵，循环打转。

### 5.2 车损怎么来

```
车损/天 = K_耐 × 单位车损        单位车损 = 地形损耗 + 战斗摊销
```

- **只算 `K_耐`（计耐久的货车）** —— 单车不计耐久、不被攻击，所以不进这笔；
- 战斗部分按"平均每场战斗掉多少耐久 ÷ 平均几场一次"摊到每天 → **战斗强度自动反映到日账上**。

### 5.3 药包怎么来

```
药包摊销 = 每场战斗的耗包 ÷ 平均几格遭遇一场 × 遭遇概率     ← 只跟"战斗人数"走，与总人数无关
```

**为什么跟战斗人数**：药包是**战斗消耗** —— 车夫和后勤不上场，就不该分摊这笔。
**为什么自变量是"格"而不是"天"**（与 §5.4 一致）：战斗是**走路走出来的**，走得快不会让遭遇变少 → 药包跟**里程**走。写"药包/天"只是把它折进日账的**表示法**，量的来源是里程。

### 5.4 按天 / 按格（**加速省的只是按天那份**）

| 归类 | 项目 | 为什么 |
|:--|:--|:--|
| **按天** | 吃喝 + 工资 | **人在就得吃** —— 与走多快无关 |
| **按格** | 车损 + **油耗** + 药包 | **走多远花多少** —— 加速省不掉 |

**这条划分是整个"动力系统"的平衡阀**：若不拆，速度一快、消耗占报酬比就会大幅下滑，**成本旋钮等于被关掉**，动力装置会强到没有取舍。
拆开之后：**加速只省得掉"按天"那份，"按格"那份照付。**
> 📌 **量纲约定**：`H` 恒为 **金/天**。所以「按格」那三项进 `H` 时，要**先用该档速度 `v` 折成日均**（`金/格 × v`）—— 折完数字会随速度变，那正是"加速省不掉"的体现。

## §6 单价与订单

### 6.1 订单报酬主式（**总消耗 × 档位倍率**）

```
该档总消耗 = 该档天数 T × 该档基准硬账 H_档
报酬       = 该档总消耗 × 档位倍率 k_档
固定单价   = 报酬 ÷ T = H_档 × k_档                  （金/天）
U_格       = 固定单价 ÷ v                            （金/格，v = 该档速度）
```

**一句话**：**先把"这条路要花多少"算成总消耗，再乘一个档位倍率** —— 这就是报价。**不是拍一个价格出来。**

| 量 | 谁的属性 | 随玩家变吗 |
|:--|:--|:--|
| `T` 该档天数 | **这条路** | 不变 |
| `H_档` 该档基准硬账 | **这个档** | 不变 |
| `k_档` 档位倍率 | **这个档** | 不变 |
| `U` 固定单价 | 由上面两个**推出** | 不变 |
| **玩家的实际人数 / 实付硬账 `H`** | **玩家自己** | 会变 —— **但不进报价** |

> 🔴 **定价基准 `H_档` ≠ 玩家实付 `H`**：报价用"**该档应有规模**"的硬账，**不用玩家此刻的实账** —— 这样才做到"**同一条路，谁跑都一样**"（用户 2026-09-16 定）。玩家省下来的、或超支的，都算自己的经营成果。

**为什么写成"总消耗 × 倍率"，而不是直接给一个价**：

| 理由 | 说明 |
|:--|:--|
| **倍率恒 > 1** | 只要规模不超该档基准，**报酬必然大于消耗 → 不可能倒亏**（§6.4-①） |
| **改锚点只动一个数** | 硬账一变，四档单价**自动跟着变**（§11 第 9 步），不必逐个重拍 |
| **可复现** | 任取一档，`U ÷ H_档` 必须等于该档倍率（§10 第 4 条） |

### 6.2 档位倍率：**逐档递增、四条独立刻度**

```
k_短途 < k_中途 < k_长途 < k_超长          四个值各查锚表（现行 2.4 / 2.7 / 3.0 / 3.6）
```

| 为什么递增 | 为什么**不能**压成一个统一值 |
|:--|:--|
| 越长的档，占用玩家时间越多、风险越大（补给线更长、遭遇更多、离家更远）→ **单位报酬必须更高**，否则"跑远"没有理由 | 压平之后，"跑远"和"跑近"的**单位收益率一样**，只剩"总时间长"一个差别 → **距离的溢价消失**，长档失去吸引力 |

> 🔴 **倍率与"叠加"是两把尺子，别混**：
> **倍率 = 单位报酬的陡度**（每一格、每一天赚多少）；**叠加 = 总报酬的陡度**（一趟接几笔）。两把尺子同时有效，合起来才是玩家真实的钱。

### 6.3 顺路叠加（**这才是玩家真实的钱**）

```
机制：同时持单无上限。一趟长线沿途经过各档边界 → 天然等于同时接了各档各一笔，路程只走一遍。

（`Uₙ` = 第 n 档固定单价（金/天）· `Tₙ` = 第 n 档天数）

短途档 报酬 = T₁ × U₁
中途档 报酬 = T₁ × U₁ + T₂ × U₂
长途档 报酬 = T₁ × U₁ + T₂ × U₂ + T₃ × U₃
超长档 报酬 = T₁ × U₁ + T₂ × U₂ + T₃ × U₃ + T₄ × U₄

天数    = 格数 ÷ v          （v = 该档速度）
消耗    = 天数 × H          （H = 玩家**实付**硬账，不是 H_档）
净利    = 报酬 − 消耗
日净收益 = 净利 ÷ 天数
```

> 📌 **记账口径必须分清**：**报酬**用档位属性（`H_档` / `k_档`），**消耗**用玩家实账。两者的差 = 玩家的经营成果。

### 6.4 什么情况才亏（**判据，不是数值**）

**① 同一档内：不会亏。**
```
报酬 − 消耗 = T × ( H_档 × k_档 − H_实付 )
∵ k_档 > 1，且按该档规模配人 ⇒ H_实付 ≤ H_档 × k_档
∴ 必为正
```
→ **"按档配人就不会亏"** —— 这就是"倍率必须 > 1"的存在理由（用户 2026-09-22 原话："**这样乘不可能倒亏**"）。

**② 跨档错配才会亏（这是设计，不是算错）。**
```
把"大档的规模"带进"小档的路" ⇒ H_实付 > H_档 × k_档 ⇒ 亏
```
→ 规模一过某点，**短档在数学上自己消失**，玩家只剩长档可跑 —— "距离即上限"的**自动实现**，不另加规则。
→ ⚠️ **若出现"按档配人还亏"，那是算错了**，回 §10 查。

**③ 高档套利（反向的错配）。**
```
用"低于该档基准"的规模去跑该档 ⇒ H_实付 < H_档 ⇒ 差额全进玩家口袋
```
要不要堵（二选一：抬高该档**天数下限** / 给档位配**最低车数**）—— **机制决策**，定了写进本文件 + `04 §8`。

## §7 支出端定价（**由日净收益反推，不拍脑袋**）

### 7.1 反推法

```
某物单价 = 该阶段日净收益 × 天数系数
```

**为什么不用"直接拍价格"**：日净收益本身**连续递增**（随人数与档位），所以价格自动跟着走；拍出来的价会在某个阶段**变成零钱**（同一把铁剑在 250 天路上还卖原价）。

### 7.2 天数系数表（**机制常数**，改它 = 改经济松紧）

| 项 | 系数 | 系数在说什么 |
|:--|:--|:--|
| 装备（单件） | **×12 天** | 约"两趟换一轮装"的节奏 |
| 加挂货车 | **×20 天** | 运力投资，回本约 20 天 |
| 火种 | **×15 天** | 只在军事基地出 → 天然后期价 |
| 招募（人） | **×25 天** | 含"日薪回本"意味 |

> 系数一变，全线价目跟着变。**这是经济松紧的唯一旋钮**。

### 7.3 装备走曲线、不走三档跳

**用户 2026-09-22 裁定**：因为"日净收益"本身连续，**价格自动连续** —— 中间档位插值即可，不必另发明规则。
**材质档（铁 → 钢 → 复合 → 特殊改造 → 旧时代）就是这条曲线的刻度。**

## §8 战斗（与移动**同刻度**，但**不通用**）

### 8.1 体力池

```
体力池 = Σ 各出战人体力        基准 / 人（有个体差异）
每回合回复 = Σ 各人体力
上限 = 2 × 回复
起手 = 满
```

| 招式档 | 微 · 轻 · 标准 · 重 · 极限（档位取值查锚表） |
|:--|:--|
| 消耗品（药包 / 零件） | 取"轻档"价位，**不占牌** |

> 🔴 **出牌没有上限**：起手 3 张（2 动作 + 1 记忆）**只是抽牌量**；回合内出牌 / 抽牌不受任何限制，**唯一闸门是体力池**。

### 8.2 伤害链

```
伤害 = 武器面板 × 招式倍数 × (1 + 角色加成%) × 攻击类型倍率
       →（护盾 → 屏障 → 护甲 → 生命）
```

| 攻击类型 | 无甲 | 软甲（布/皮） | 硬甲（铁/钢） |
|:--|--:|--:|--:|
| 打击 | ×0.9 | ×1.0 | **×1.3** |
| 斩击 | ×1.1 | **×1.2** | **×0.9** |
| 刺击 | ×1.1 | ×0.9 | ×0.9 |

> ⚠️ **倍率作用于整次伤害、一直进到生命**（**统一作用于护盾 / 屏障 / 护甲 / 生命四层**）。**通用减伤率已取消**（会让相性被纯优乘数抹平）。
> 🔴 **2026-10-10 用户裁定**：**打击无甲 0.95 → 0.9**（"前半场武器"手感更明显）· **刺击 1.0/1.0 → 0.9/0.9**（削弱成"两头都不吃"—— 情报不足时选它是**赌博**）。配套放宽「三型整场加权总量齐平」的约束（原差 4% 内 → **~10% 内**），并新增约束「**三型都必须有擅长的场景**」。详见 `第4A类 §4.2`。
> **护甲**只由防具给（开战赋值 · 本场持久 · 战毕复位）；**护盾**只由盾牌给（回合末清空 · 可给队友叠）。
> 🔴 **敌我共用此链**（2026-09-29 定）—— 敌人造成的伤害、以及敌人获得的护盾 / 反击 / 各类状态，**一律走同一个公式**；**不为敌人开第二套算式**（对等原则见 `0A 第4A类 §5.0`）。

### 8.3 敌人数值

```
敌方总血池 = 我方血池 × 系数        普通 / 精英各一档（Boss 单独设计）
承伤 = 血池百分比 × 人数系数          普通 / 精英各一档
人数系数 = √(3 ÷ 出战人数)
```

> **个数只摊分总血池，不进总血公式**（3 只强盗 = 1 只灰烬兽，总血一样）。
> **回合数目标**：普通 / 精英 / Boss 各有一个区间（取值查锚表）；Boss **不锁血、单独设计、不可普通撤**。

### 8.4 野外自愈与心肺

| 项 | 算式 |
|:--|:--|
| **肺** | 战斗中**每回合体力回复** ×(1 + 每点加成 × 等级) |
| **心脏** | ① 体力**上限** ×(1 + 每点加成 × 等级)；② **战斗外每日自愈速率** |
| 每日自愈 | **随血池等比缩放**（血池越大，绝对回血越多，但天数比例不变） |

> 🔴 **野外体力不挂器官**（与 §2 解耦）—— 野外力气由"**池（固定 100 / 日回 50）+ 攒池节奏**"决定，每格消耗恒定；**与肺 / 心脏 / 人数 / 个体全部无关**。

## §10 换锚点后的自检（**方法，不是样例数值**）

改完锚点、按 §11 算完，**必须过这六道闭合检查**。任何一道不闭合 → 说明改错了地方：

| # | 检查 | 判据 |
|:--:|:--|:--|
| 1 | **编制闭合** | 后勤 = 车夫 + 战斗 + 特殊；总人数 = 2 × 三者之和（**自己算出来的总数必须能反推回车数**） |
| 2 | **工资可复现** | **任取两档已落库的工资值**，代回 §3.3 公式都能算出原值 —— 差 1 金就是公式错了 |
| 3 | **硬账闭合** | `H` = 四件之和，且四件**每件都能独立算出**（不许有一项是"凑出来的差额"） |
| 4 | **倍率可复现** | 任取一档，`U ÷ H_档` 必须 = 该档倍率；把倍率置 1 → 该档报酬必须**正好等于**消耗（不亏不赚） |
| 5 | **单价互洽** | 同一档的 `U_格 × v` 必须 = 固定单价 `U`（两种写法同值） |
| 6 | **叠加可复现** | 按 §6.3 四式算，**长档报酬必须 = 短档报酬 + 增量**（无重复计数、无漏项） |

## §11 改锚点后的重算顺序（**本文件的核心用法**）

> **从第 1 步进，一路跑到第 12 步，不要跳。** 每步只依赖它上面的步骤。

```text
1. 锚表（04 §0.1）
   ├─ 改哪个锚，就只动哪个锚
   ↓
2. 移动链：S、c  →  v = round((S − c_侦) / c)
   ↓
3. 编制链：车数 K → 车夫(=K) → 后勤(=三者之和) → 总人数(=2×) → 计耐久车 K_耐
   ↓
4. 补给链：P → 补给钱/天（§4.1）· 补给格/天（§4.2）
   ↓
5. 工资链：各岗人数 − 初期核心 → × 日薪（§3.3）
   ↓
6. 车损链：K_耐 × 单位车损
   ↓
7. 药包：按 P_战 查表
   ↓
8. 硬账 H = 补给 + 工资 + 车损 + 药包
   ↓
9. 单价 U_档 = H_档 × k_档（逐档）→ U_格 = U_档 ÷ v
   ↓
10. 订单四档 = 叠加（§6.3）→ 净利 → 日净收益
   ↓
11. 支出端定价 = 日净收益 × 天数系数（§7.2）
   ↓
12. 可达距离：单程 = W0 × (q ÷ q0) × K ÷ (K + P_战 + P_特) ÷ 2
   ↓
   回写 04 / 0A / 14 / 08 的**求值结果**（公式不动）
```

**会互相咬合、必须一起改的几组**：

| 改了这个 | 必须同时重算 |
|:--|:--|
| 人数 `P` | 补给 · 工资 · 硬账 · 单价 · 四档 · 装备价（§4→§7 全链） |
| 车数 `K` | 车夫 · 总人数 · 计耐久车 · 车损 · 可达距离 |
| 单车格数 `q` | 可达距离 · 升级天花板（§2.5） |
| 速度 `v`（或 `S` / `c`） | 天数 · 消耗 · 日净 · 单价/格 · 油费 |
| 粮价 / 密度 / 补水率 | 补给钱（价）· 补给格（密度）· 硬账 · 单价 |
| 血池 / 承伤 | 敌人数值 · 回合数 · 药包摊销 |
| 硬账 `H` | 单价 · 四档净利 · **全套支出端定价** |

> 🔴 **第 5b 条是第 5 条的延伸、也是它的例外封口**：既然"提速 = 省天数 = 打折 91% 的账"，那**任何压低 `c` 的手段都必须一律作废** —— 包括车轮（已删）。**现在能变快的只剩两条**：**动力抬 `S`**（`v = (S − c_侦)/c` 里 `S` 变大）与**攒池**（用掉 `S_max` 那一半）。**这两条都不改 `c`、都不改按天计的硬账结构。**
