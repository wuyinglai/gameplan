## 5. 内部事件系统（5.3）

> 🔴 **2026-09-29 用户定：内部事件频率必须压低。** 原话：「**内部事件触发概率要降低一点……绝对不能可能每天都触发，甚至不要每五天就触发一次，因为内部事件惩罚很重**」「**人越多触发概率越高**」「**或者说士气低才会触发……或者说特定的，比如说走得太累或者说饿之类的才会触发，不然的话惩罚太严重了**」。

### 5.1 核心原则

1. 🔴 **三重闸门，缺一不触发** —— 内部事件**不是"每天摇一次骰子"**，而是**先有压力 → 再受间隔限制 → 最后才抽**。
2. 🔴 **无压力 = 概率 0** —— 队伍状态好时**根本不进入计算**（旧文件"状态好时概率可为 0%"**升格为硬规则**）。
3. 🔴 **惩罚越重，频率越低** —— 内部事件立刻咬钱 / 咬货 / 咬士气，所以**频率上限由总冷却兜底**，**与压力多大无关**。
4. 🔴 **人越多，越容易内爆** —— **人数是"放大系数"，不是"加项"**：同一份压力，50 人的商队比 14 人更容易炸。
5. **每个内部事件必须有解决手段**（花补给 / 花时间 / 花零件 / 改路线 / 花钱）。🔴 **惩罚只能是"要价"**（掉钱 / 货 / 士气 / 强制休整），**绝不剥夺**（铁律 8）。
6. 🔴 **内部事件不能只会爆坏的** —— **必须留正面的口子**（`士气 · 互助`），否则士气一低必然雪崩，玩家没有翻盘手段。

### 5.2 三重闸门（**执行顺序**）

```
闸门 1 · 压力源     无压力 → 概率 0，直接跳过
   ↓ 有压力
闸门 2 · 总冷却     距上次内部事件 < N 天 → 概率 0，跳过
   ↓ 冷却已过
闸门 3 · 抽签       概率 = 基准频率 × 人数系数 × 压力强度  且  ≤ 每日上限
```

**闸门 1 · 压力源清单**（满足**任意一条**即开门）：

| 压力源 | 判据 |
|:--|:--|
| **士气低** | 士气 ≤ 阈值 |
| **饿 / 渴** | 补给不足到下一个安全点，或补给为 0 |
| **太累** | 当日把回复的体力全花在路上（**池见底**）/ 连续多日走满 |
| **伤病** | 有重伤员 / 严重重伤 |
| **车况** | 车况低 / 抛锚 |
| **缺件** | 零件不足 / 为 0 |
| **恶劣天气** | 暴雨 / 酷热 / 严寒 / 重雾 / 灰烬风 / **灰烬风暴** |
| **灰烬污染** | 携带灰烬货 / 污染扩散 |
| **货损** | 货损严重 |

> 🔴 **"太累"与"饿"是与"士气低"并列的独立扳机**（用户点名）—— **不是士气的子项**。理由：**它们是身体信号，比情绪出现得更早**；队伍情绪还撑得住、但身体已经走崩了 —— 这才是长途的真实体感。

**闸门 2 · 总冷却**：**每次内部事件后 ≥ N 天不再抽**。
- 🔴 **N 由 `23` / `24` 定**（设计意图：**绝不短于"一周一次"**，用以保证"**不会每五天就爆一次**"）。
- ⚠️ 与**同类降权**是两件事，**并存**：**总冷却** = "这段时间**不再爆任何内部事件**"；**同类降权** = "可以爆，但**别同一类连爆**"。

**闸门 3 · 概率**

```
内部事件概率 = 基准频率 × 人数系数 × 压力强度    （压力强度 0~1）
内部事件概率 = min(上式, 每日上限)

基准频率  = 常量（有压力时的基础概率）
人数系数  = 人数轴的单调递增函数（人越多越高）
压力强度  = 各压力源等级之和（0 = 无 / 3 = 极重）
每日上限  = 即使压力拉满也封顶（保证"不会每天必爆"）
```

> ⚠️ **以上 4 个系数（基准频率 / 人数系数曲线 / 压力强度权重 / 每日上限）的唯一来源 = `23 §2.9` 的等式 + `24_数值计算器.html`** —— 本文件**不手写**（工序铁律：**输出层不手写**）。

### 5.3 压力源的强度分档

> 🔴 **各表只定「等级」，不定「百分比」** —— **等级 → 权重的换算见 `23 §2.9`**。
> 等级定义：**0 = 无压力（不开门）· 1 = 轻 · 2 = 中 · 3 = 重**。

**① 士气（🔴 主闸门 · 低才开门）**

| 士气 | 等级 |
|:--|:--:|
| 7 ~ 10 | **0**（不开门） |
| 5 ~ 6 | 1 |
| 3 ~ 4 | 2 |
| 1 ~ 2 | 3 |
| 0 | **强制撤退**（不抽普通内部事件） |

**② 补给（饿 / 渴）**

| 补给状态 | 等级 |
|:--|:--:|
| 富足（到下一站还有大量余量） | **0** |
| 刚好够（几乎无余量） | 1 |
| 不够（到不了下一站） | 2 |
| 已为 0（短缺） | 3 |

**③ 体力（太累）· 🆕 本版新增**

| 当日野外体力（池） | 等级 |
|:--|:--:|
| 有余量 | **0** |
| 当天回复的体力全花在路上（池见底 —— 正常 3 格 = 45 点即近乎花完） | 1 |
| 连续走满 ≥ 2 天 | 2 |
| 连续走满 ≥ 3 天 | 3 |

**④ 伤病**

| 重伤 / 严重重伤人数 | 等级 |
|:--|:--:|
| 无 | **0** |
| 1 人 | 1 |
| 2 人 | 2 |
| 3 人及以上 / 有严重重伤 | 3 |

**⑤ 车况**

| 商队耐久 | 等级 |
|:--|:--:|
| 完好 | **0** |
| 受损 | 1 |
| 危险 | 2 |
| 濒毁 / 抛锚 | 3 |

**⑥ 零件**

| 零件状态 | 等级 |
|:--|:--:|
| 足够 | **0** |
| 不足 | 1 |
| 为 0 | 2 |

**⑦ 天气**

| 天气 | 等级 |
|:--|:--:|
| 晴朗 / 阴天 / 小雨 / 高温 / 寒潮 / 浓雾 | **0** |
| 暴雨 / 酷热 / 严寒 / 重雾 | 1 |
| 灰烬风 | 2 |
| 灰烬风暴 | 3 |

**⑧ 灰烬污染**

| 状态 | 等级 |
|:--|:--:|
| 无灰烬货 | **0** |
| 携带灰烬货 | 1 |
| 灰烬货扩散 | 2 |

**⑨ 货损**

| 货损 | 等级 |
|:--|:--:|
| 轻微 | **0** |
| 严重 | 1 |
| 极重 | 2 |

**🔴 人数系数（用户定 · 人越多越高）**

- **人一多，同一份压力就更容易炸** —— 现实就是"人越多越难管"（`04 §0.7.7` 管理成本三层的第 ① 条）。
- 🔴 **它是"系数 / 乘数"，不是"加项"** —— 加项会让"**人少 + 压力重**"和"**人多 + 压力轻**"算出同样的概率，那**不符合直觉**；乘数才有"**14 人扛得住、50 人扛不住**"的效果。
- ⚠️ **曲线形状与取值见 `23 §2.9`**（本文件只定"**单调递增**"这条性质）。

### 5.4 内部事件类型总纲（**7 类 · 28 小类**）

> 🔴 **为什么旧文件没有这张表**：旧概率公式有 **9 个修正项**（士气 / 补给 / 零件 / 车况 / 重伤 / 天气 / 灰烬 / 货损 / 扎营），但**修正项只管"提高概率"，爆发的样子却是散的**。
> 🔴 **新做法：一个压力源配一类事件** —— **修正项 = 概率源，类 = 爆发形态**。→ **玩家哪儿疼，就爆哪类**（补给见底绝不会爆"车坏了"，因为车况压力为 0）。

| 内部类 | 对应压力源 | 小类 | 是什么形式 |
|:--|:--|:--|:--|
| **士气** | 士气修正 | **抱怨** · **争执** · **恐惧** · **想离队** · 🟢**互助** | 抱怨 = 累/饿/走太久（掉士气、不改行动）· 争执 = 路线分歧/分配不公（掉士气、可能卡一天）· 恐惧 = 进灰烬区/刚死了人（掉得多、可能拒走）· 想离队 = 士气长期低（**只闲置、绝不挖走**）· 🟢互助 = 有人主动搭手，**士气回升** |
| **伤病** | 重伤修正 | **恶化** · **感染** · **灰蚀后遗** · **严重重伤** · **强制休养** | 恶化 = 重伤没治 → 更重 · 感染 = 伤口脏了（掉血快、要用药）· 灰蚀后遗 = 高灰区待久了，带着灰蚀进下一场 · **严重重伤 = 伤到完全上不了阵** · 强制休养 = 必须停 N 天 |
| **补给** | 补给修正 | **断粮** · **缺水** · **分配争执** · **吃坏肚子** | 断粮 = 粮见底（掉士气 + 全员掉血）· 缺水 = 比断粮更急 · 分配争执 = 不够分（掉士气）· 吃坏肚子 = 全员轻伤一天 |
| **零件** | 零件修正 | **不够修** · **拆东墙** · **锈蚀受潮** | 不够修 = 要修没件（凑合或停下）· 拆东墙 = 拆一台车补另一台（**短期过关、长期欠账**）· 锈蚀受潮 = 恶劣天气伤零件（库存变少） |
| **车** | 车况修正 | **抛锚** · **车轮** · **车架** · **车篷** | 抛锚 = **车轮或车身损坏 → 车无法继续前进，必须修** · 车轮 = 磨/爆/陷（直接决定能不能走）· 车架 = 烂路托底（**烂路上磨损翻倍**）· 车篷 = 篷子破了（**雨天 / 恶劣天气货受损**）—— 部位表见 `第3A类 §2.2A` |
| **货** | 货损修正 | **受潮** · **丢货洒落** · **超载** · **变质**⚠️ | 受潮 = 雨天（粮、药坏）· 丢货洒落 = 颠掉/被抢 · 超载 = 消耗涨、车损快 · 变质 = ⚠️ **待定**（挂"保温箱要不要开易腐"，用户未决） |
| **灰烬** | 灰烬污染修正 | **污染扩散** · **弃货抉择** · **灰烬货争议** | 污染扩散 = 沾染的货开始传（**会蔓延到好货**）· 弃货抉择 = 扔（亏钱）还是不扔（传开）· 灰烬货争议 = 队员不愿运灰烬货（掉士气或妥协） |

🔴 **三条结构注**：
- **天气不进类**（它是**权重来源**，见 §5.5）；**扎营不进类**（它是**手段**，不是事件）。
- **小类数量不齐是正常的** —— 判据是"**这一小类有没有独占的场合或代价**"，**不凑数**（项目老规矩：不许为对称硬编）。
- 小类 = **权重表的格子**（与 §3.3 外部侧同一逻辑）。

### 5.5 天气与内部事件接口

不同天气**提高特定内部类的权重**（**它是"权重来源"，不是"独立事件类"**）：

| 天气 | 抬权重的内部类 / 小类 |
|:--|:--|
| 暴雨 | **货**（受潮）· **伤病**（恶化）· **士气**（抱怨）· 落脚抉择（是否扎营避雨） |
| 酷热 | **补给**（断粮 / 缺水争执）· **伤病**（恶化）· 路线抉择（是否绕路找水） |
| 严寒 | **士气**（发冷）· **伤病**（怕冷）· 抉择（是否消耗补给取暖） |
| 重雾 | **士气**（是否继续赶路争执 / 迷路焦虑 / 守夜压力） |
| 灰烬风 | **灰烬**（污染货争议）· **伤病**（恶化）· 抉择（是否继续进灰烬区） |
| 灰烬风暴 | **灰烬**（污染恐慌）· **伤病**（恶化）· 抉择（是否撤退 / 是否丢弃灰烬货） |

> 🔴 **"天气改善 ≠ 内部变好"**：天气只**加减权重**，**不改变闸门与冷却** —— 暴雨天不必定爆内部事件，晴天后也不平白变安全。
