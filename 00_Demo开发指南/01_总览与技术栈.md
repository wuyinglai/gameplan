## 1. 项目是什么

《余烬商队》是一个**末世废土题材的商队跑商游戏**：玩家经营一支商队，在大地图上从一个城市跑到另一个城市，买货卖货、接订单送货赚钱，路上会遇到敌人进入卡牌战斗。

**本版定位 = 极简测试版（数值验证原型）：**
- 目的不是做完整游戏，是**验证核心玩法循环到底好不好玩**，并**暴露需要改的机制和数值**。
- 所有系统从 `0A_权威系统文档/` 原样搬过来用，**不重新设计**。
- **没有任何剧情、没有任何支线、不需要任何「合理」解释**——只要能跑、能测就行。
- 数值一律给**初值/基准值**，全部带 ⚠️ 标记，必须靠实测调优后再锁。

**核心玩法循环（本版要验证的）：**
```
在城市接订单/买货 → 400×400 大地图走格子（每天 50 点野外体力）→ 路上事件/战斗/灰烬生态
→ 到达目的地卖货/交订单赚钱 → 补补给 → 攒够本钱与本事
→ 灰烬兽最终战 → 击败即通关
```

**玩家定位：** 商人不是救世主。跑商赚钱、攒够本钱是主线，最终 boss 就是「最后打一下」，无需任何剧情包装。

**本版规模（一句话）：** 单张 **400×400** 地图 · **76 个地点** · **3 座城**（1 大 + 2 小）· 商队 **14 人 / 4 辆车（3 货车 + 1 单车）** · **一局制**（无存档）。

## 2. 测试版目标

| 目标 | 说明 |
|:-----|:-----|
| 验证核心循环 | 跑商 → 补给管理 → 卡牌战斗 → 讲价 → 赚钱 → 攒够 → 最终战，是否好玩 |
| 暴露问题 | 哪些机制「想得好玩实际不好玩」、哪些数值明显失衡（太肝/太无聊/太随机） |
| 快速试玩 | 玩家能玩到「出发→战斗→到城→赚钱→打 boss→通关」的完整一局 |
| 数值基线 | 给出一套可测初值，跑几局后用日志核对、再调 |

**本版不追求：** 剧情叙事、世界观自洽、城市经营、长线内容。这些后续正式版再做。

## 3. 技术栈（2026-09-11 重新制定：网页版）

| 项目 | 要求 |
|:-----|:-----|
| 语言 | **HTML + CSS + 原生 JavaScript（ES6）** |
| 框架 / 依赖 | **零**：不用 React/Vue、不用 npm、不用任何构建工具、不装任何第三方库 |
| 画面 | 大地图用 `<canvas>` 2D 绘制；菜单/交易/订单/战斗界面用 DOM + CSS |
| 交互 | **鼠标点击为主** + 键盘：`w/a/s/d`（或方向键）移动、数字键选菜单 |
| 运行方式 | **双击 `index.html` 直接用浏览器打开**（无需服务器、无需安装）；也可本地 http server |
| 自测 | 核心数值与结算逻辑写成**纯函数**，用 Node 直接跑断言核对；界面用浏览器预览核对 |

> **UI 定位**：重点是验证玩法和数值，画面**允许粗糙**——先用纯色方块 / 简单图形 / 文字占位，好玩了再谈美术。
> 一局制（无存档），方便反复开新局测不同数值。
>
> **为什么不用 Python / 游戏引擎**（决策记录）：
> - 本机 Python **无 GUI 模块**（`tkinter`、`pygame` 均不可用），"Python + 命令行/ASCII"路线跑不起来；
> - 网页版**零依赖、双击即玩、跨平台**，且与已有工具链（浏览器版地图编辑器 + `地图坐标_400导入用.json`）**天然打通**，地图数据可直接被游戏读取；
> - 改一处即可在浏览器即时预览，迭代最快 —— 正合 Demo 验证玩法的目的。
> - **代价**：它不是 Unity/Godot 那种正式游戏引擎；但 Demo 只验证玩法与数值，**将来正式版若换引擎，玩法与数值逻辑可整体迁移，不白做**。

### 3.1 代码可移植性（硬指标：测试版 → 正式版要能搬）

**先想清楚一件事：真正值钱、需要搬到正式版的是「规则 + 数值」，不是「画面」**。画面随引擎走，本来就得重写。所以代码**强制分三层**，让"能搬的那部分"一点不动地搬走：

| 层 | 文件 | 装什么 | 搬到正式版时 |
|:--|:--|:--|:--|
| **数据层** | `data.js` | 全部数值、配置、地图坐标、物价表、卡牌表、敌人表 | **原样搬**（必要时转成 JSON / Excel / 引擎数据表） |
| **规则层** | `core.js` | 纯逻辑：经济与买卖、战斗结算、成长与记忆、补给与失败、订单、地图寻路、灰度 | **规则照搬**：全是纯函数、不碰任何界面；即便正式版换语言（C# / GDScript），也只是**按语法改写**，逻辑一字不改 |
| **表现层** | `index.html` + `ui.js` | canvas 绘制、菜单、按钮、输入响应 | **只有这层需要重写**（唯一随引擎变的部分） |

> **铁律**：`core.js` 里**绝对不许出现** `document` / `canvas` / DOM / 任何界面调用。规则层只做「吃数据 → 吐结果」，界面层只做「把结果画出来 + 收输入」。
> **好处**：① 规则层可直接在 Node 里跑自测，不用开浏览器；② 正式版无论换 Unity / Godot / 还是继续网页，**数据和规则整段搬走，只重画表现层**。
>
> **如果正式版真要用 Unity / Godot**：Demo 的 `data.js`（数值）与规则设计 100% 用得上，JS 规则层按语法改写成 C# / GDScript 即可；**不会白做**。（什么时候换、要不要换，留到正式版阶段再定，不提前锁死。）

## 4. 运行环境

- 任意现代浏览器（Chrome / Edge / Firefox 均可），**无需安装任何运行库**
- **零依赖、开箱即跑**：双击 `index.html` 即进入游戏
- 跨平台（Windows / macOS / Linux）
- **地图与配置数据内嵌为 JS 常量**（不靠 `fetch` 读本地 JSON，避免 `file://` 跨域限制，保证双击可玩）

## 5. Demo 范围边界（极简测试版）

### ✅ 要做（把体系全搬过来）
| 系统 | 范围（本版） |
|:-----|:-----|
| 大地图移动 | **400×400 网格**，每天 **50 点野外体力**、每格 **20 点**、满速约 2.5 格/天、均速约 2 格/天（体力系统，详见第 1A 类 §2） |
| 地点 | **76 个**：1 大城 + 2 小城 + 12 城镇 + 10 驿站（4 有节点信号中继 / 6 九城时代损坏无节点）+ 36 村庄 + 大遗迹 5 + 小遗迹 10 |
| 补给系统 | 食物、水、零件、商队耐久、士气、车厢 |
| 卡牌战斗 | 3 名初始角色；**起手抽 3 张（2 动作 + 1 记忆）**，**出牌无上限**（唯一闸门 = 体力池），状态效果，可撤退（详见 `17`） |
| 订单与讲价 | 送货/收购订单；买/卖/接单三类讲价（5 轮拉锯） |
| 灰烬生态 | 灰度两层、腐蚀(≥50)、感染(≥70)、灰兽原生+感染、接触选择、灰烬风暴短时天气 |
| 节点 | 大城节点反应炉 = 通关触发动作；驿站节点 = 信号中继 |
| 角色成长 | 3 初始角色 + 记忆/火种（轻量）；遗迹武器终极技门槛（轻量） |
| 遗迹 | **大遗迹 5 / 小遗迹 10**（不再按"产武器 / 产记忆手册"区分）；轻量做，供终极技门槛测试 |
| 招募 | 轻量 1~2 人（特殊人员，如账房，影响讲价/补给） |
| 敌人 | 强盗、野兽、灰烬兽（普通）+ **灰烬兽（最终 boss，随便安、无剧情）** |
| 随机事件 | 路上随机：补给/伏击/商人/风暴预警/灰兽接触 |

| 不做 | 说明 |
|:-----|:-----|

| 装备模块 | 无（感染防护仅留机制接口，本版感染靠城市治愈） |

| 传送 | 无 |
