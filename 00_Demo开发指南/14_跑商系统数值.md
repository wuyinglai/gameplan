## 一、定价总则（2026-09-08 用户口径 · 替代原「价格指数 M」方案）

> **原「大城 ×1.00 / 村庄 ×1.60 价格指数」方案已作废**——那是 AI 自编、未查文件。以下为用户当场定的更简单方案。

### 1.1 核心规则

1. **每个地点自己有一套价**（不是靠系数乘出来）。大城一套、小城一套、城镇一套、驿站一套、村庄一套。
2. **大多数小城共用同一套模板**——不逐城另编。
3. **有特产的城，就把该特产的价格调低一点**（不需要复杂系数，直接调低即可）。
4. **每天在「正常价」上下随机浮动**：
   - 价格 = 正常价 × (1 + δ)
   - δ 取 **三角分布**，中心（δ=0，即正常价）概率最高，**偏离正常越远概率越小**。
   - 波动幅度：一般货物 **±20%**；战略资源（火种 / 灰烬材料）**±10%**。
5. **卖出同样按「该城的收货正常价 + 随机波动」**，不用买入系数反算。
6. **货物可以卖到任何地点**：城市、城镇、驿站、村庄都能收货（城镇 / 驿站 / 村庄收货价更高或更低由各自的收货正常价决定，玩家自己挑地方卖）。

### 1.2 每日价格波动算法（可直接实现）

```python
import random

def daily_price(base_price: int, spread: float = 0.20) -> int:
    """每日价格：正常价附近概率最高，越偏离概率越小。"""
    delta = random.triangular(-spread, +spread, 0.0)   # 三角分布，众数=0
    return max(1, round(base_price * (1 + delta)))
```

- `random.triangular(low, high, mode)`：`mode=0` 即正常价出现概率最高，越往两端概率越低——正是用户要的「偏离正常越多，概率越小」。
- 每个地点、每种货物、每天各摇一次（并入第 10 类 RNG 种子体系，保证可复现）。
- 卖出价同法：`sell = daily_price(base_sell, spread)`。

### 1.3 各地点价格模板（默认一套，⚠️ 具体每座城定价由用户定）

| 地点类型 | 定价方式 | 相对大城的水平 |
|:--|:--|:--|
| **大城** | 大城模板（基准） | **最低**（第2A类：功能最完整、**物价最低**） |
| **小城** | 小城模板（大多数小城共用一套） | 跟大城一档、**略贵一点** |
| **小城（本城特产）** | 该特产货在小城模板基础上**直接调低** | 明显低于大城（产地便宜） |
| **城镇** | 城镇模板 | 高于小城（第2A类：价格高于城市、库存有限） |
| **驿站** | 驿站模板 | 与城镇平级；**零件 / 药包比城镇便宜**（用户定：城镇 80 / 驿站 70） |
| **村庄** | 村庄模板 | **最贵**（第2A类：功能最少、**物价最高**） |

> 具体每座城（1 大城 + 2 小城 / 12 城镇 / 12 驿站 / 20 村庄）的逐货定价**由用户定**，AI 不编坐标、不编逐城价目表。

> 用户 2026-09-08 定：**利润随阶段递增——前期约 70~80%，中期 100%，后期 120%**；并给出各档倍率：短途 ×1.7、中途 ×2.0、长途 ×2.1、超长途 ×2.5。

### 5B.4 订单类型（4 大类 · 引用《订单与贸易系统设计方案》§1.1）

| 类型 | 内容 | 时效 | 需要接取？ | 失败条件 |
|:--|:--|:--:|:--:|:--|
| **送货订单** | 把货物运到指定收货地 | 有期限 | ✅ 需要 | 严重超时 → 失败 |
| **护送订单** | 护送某人 / 某物到指定城市 | 有期限 | ✅ 需要 | 严重超时 → 失败 |
| **收购订单** | 高价收购指定物品（城市 / 个人） | **无期限** | ❌ 不用接 | 无——交货就给钱 |
| **悬赏订单** | 击杀指定敌人 / Boss | 无期限 | ❌ 不用接 | 无 |

> 来源：市场 / 商会 / 悬赏板 / 领主·城主 / 个人 NPC / 酒馆（同方案 §1.2）。
> 收购、悬赏**不用专门接**——带着货到了直接交、杀了目标拿凭证直接领，世界更活（同方案 §1.3）。
> 收购 / 悬赏有随机时限：被别的商队 / 赏金猎人完成就消失（同方案 §1.4）。

### 5B.5 交付结果与违约（用户 2026-09-08 定）

| 交付情况 | 结果 |
|:--|:--|
| **早到** | **额外声望奖励**（可能还有小额奖金，⚠️ 待定） |
| **正常时间到** | 无额外奖励、无惩罚，按约定付酬 |
| **延期（超期但可补救）** | **声望损失 + 佣金减少**（还是给钱，只是少给） |
| **超过一定期限（严重超期）** | **大量声望损失 + 不支付报酬** → 订单失败 |

> 货物被毁**不算订单失败**，只损失货物本身（《订单与贸易系统设计方案》§1.5）。
> 收购 / 悬赏无接取，不存在失败，只可能被别人完成而消失。

### 5B.6 接单规则与其它

| 项 | 规则 | 出处 |
|:--|:--|:--|
| **同时持单上限** | **无上限**（可以无限接订单） | 《订单与贸易系统设计方案》§六「玩家可以无限接订单」 |
| 期限 | **天数 × 1.3**（天数 = 格距 ÷ 2） | 修正 doc04 原式（原按 3 格/天，现按 2 格/天） |
| 讲价加酬 | 接单时可谈判提高酬金 | 第 10A 类 §一 |
| 难度分级 | 很简单 / 简单 / 正常 / 困难 / 很困难（刷新率越低、奖励越高、被 NPC 抢走得越慢） | 同方案 §四 |
| 刷新 | 每天随机刷新，类型概率待定 | 同方案 §五 |
| 竞争者窗口 | 好订单 1~2 周（游戏内）会被别的商队接走 | 第 10A 类 §一 |

> **为什么不限持单（用户原话）**：A→B 路上有 C 点，去 C 的订单和去 B 的订单顺路，就该同时接、顺路一起做，路上还能卖货——**多接顺路订单正是赚钱方法**，不该禁。

### 5B.7 ⚠️ 量级分歧说明

第 2.1 类给的「长线一趟真实收益 ≈ 20,000~30,000 金」是**小队口径（30 金/天）**；测试版按 **12 人商队（250~1,500 金/天）**走，同档订单金额会大一个量级（短途一趟已接近 2 万）。**这是口径差不是错误**，但意味着：

- 实测时优先观测：**「玩家多久能攒够一颗火种 / 一件高级装备」** 是否在预期区间。
