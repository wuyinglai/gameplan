# 05 · 数据结构（极简测试版）

> 《余烬商队》极简测试版 · 开发指南第 5/11 份
> 用途：定义代码里**核心数据结构**（Python 标准库 `dataclass` / 普通类）。编写代码的 AI 照此落地，字段名与数值对齐 `01~04`。
> 口径：2026-09-07 裁定——无剧情、200×200、3 城、极简、纯测好玩与数值。

---

## 1. 总原则

- **仅用 Python 标准库**：结构用 `dataclasses.dataclass` 或普通类；集合用 `dict` / `list` / `tuple`；枚举用字符串常量（避免引入 `enum` 依赖，简单够用）。
- **可变状态与常量分离**：商队可变状态放 `Caravan` 实例；世界固定配置放 `config.py`（见文档 08），不在结构里硬编码数值。
- **一局制、无持久化**：不需要序列化/存档，进程退出即结束。结构里不加 `save()` / `load()`。
- **坐标约定**：地图格用 `(x, y)`，`x` 列 `0~199`，`y` 行 `0~199`；`(0,0)` 在左上角。

## 2. 核心结构

### 2.1 Caravan（商队 = 全局游戏状态核心）

```python
@dataclass
class Caravan:
    name: str = "余烬商队"
    day: int = 1                      # 当前天数，从 1 开始，无上限（但防死循环，见 09）
    gold: int = 300                   # 金钱（⚠️ 初值，文档 04 §1）
    food: float = 10.0               # 食物份（⚠️ 初值）
    water: float = 8.0               # 水份（⚠️ 初值）
    parts: int = 3                    # 零件（⚠️ 初值）
    morale: int = 6                   # 士气 0~10（⚠️ 初值）
    durability: int = 100             # 商队耐久 0~100（抛锚=0）
    pos: tuple = (0, 0)               # 当前格坐标
    members: list = field(default_factory=list)      # Character 列表，初始 3 人
    cargo: dict = field(default_factory=dict)        # {Goods: 数量} 货舱
    ember_core: bool = True           # 持有余烬核心（抵债包裹获得，激活钥匙不消耗）
    junk_items: list = field(default_factory=list)   # 抵债包裹里的无用旧件（仅氛围，不影响机制）
    orders: list = field(default_factory=list)       # Order 列表，持单无上限（已废除"最多 3"，见第10A类 / 文档04 §7）
    memories: list = field(default_factory=list)     # 已植入记忆（轻量）
    remodels: list = field(default_factory=list)     # 已装身体改造项
    fire_seed: int = 0                # 火种（战略资源，轻量）
    relics: list = field(default_factory=list)       # 遗迹武器 / 记忆手册（终极技门槛测试）
    reputation: dict = field(default_factory=dict)   # {city_id: int} 城市声望（轻量记录）
    npc_trust: dict = field(default_factory=dict)   # {npc_id: int} 个体信任（轻量）
    node_activated: bool = False      # 大城节点是否已激活（通关触发标志）
    outcome: str = ""                 # 结算结果："win" / "lose" / ""（进行中）
```

> 余烬核心开局即 `True`：抵债包裹获得，混在 `junk_items` 无用物中，UI 不提示其用途（文档 02 §3、03 §7）。`junk_items` 仅为氛围，不进任何机制判定。

### 2.2 Character（角色 / 战斗人员）

```python
@dataclass
class Character:
    id: str
    name: str
    job: str                         # "护路人" / "荒野射手" / "修补师"（初始 3 人，文档 04 §1）
    hp: int = 0
    max_hp: int = 0
    armor: int = 0                   # 常驻护甲类被动（骨甲植入等，文档 06A 第15节）
    statuses: list = field(default_factory=list)   # Status 列表（标记/流血/护盾/…）
    memory_slots: list = field(default_factory=list)  # 已装记忆
    remodels: list = field(default_factory=list)      # 本体改造（第三成长轴）
    traits: list = field(default_factory=list)        # 特殊人员特质，如 "账房"（影响讲价/补给）
    alive: bool = True
```

初始数值（文档 04 §1 / 03 §5）：
- 护路人：max_hp 68
- 荒野射手：max_hp 40
- 修补师：max_hp 46

> 招募进来的特殊人员（如账房）也用同一结构，`job` 标职业、`traits` 标特质；初始 3 人 `traits` 为空。

### 2.3 Goods（货物）

```python
@dataclass
class Goods:
    id: str
    name: str
    base_price: int      # 大城基准价（文档 04 §6）
    weight: int = 1      # 占货舱格数（本版可全 1，留扩展）
    is_ash_special: bool = False   # 灰烬特产（高灰区富集，文档 03 §6）
```

货舱：`caravan.cargo` 为 `{Goods: 数量}`，货舱总容量 = 货车 `cargo_capacity`（3 货车×300 = 900 格，见第 3A 类 §3 / §4.5.5）。余烬核心 / 火种 / 金钱不占格。

### 2.4 Location（地点，基类 + 子类用 `type` 区分）

```python
@dataclass
class Location:
    id: str
    name: str
    type: str            # "big_city" / "small_town" / "station" / "village" / "wild" / "obstacle"
    pos: tuple
    has_node: bool = False        # 仅大城 True
    node_activated: bool = False   # 大城节点是否已激活
    functions: set = field(default_factory=set)   # 见下表功能标志
    goods_stock: dict = field(default_factory=dict)   # {Goods: 当前价}（买卖用）
    orders_available: list = field(default_factory=list)  # 可接订单
    npcs: list = field(default_factory=list)        # 固定 NPC（讲价/信任/招募）
    specialty: str = ""           # 特产 id（小城产出，文档 02 §2）
    station_has_node: bool = False  # 驿站节点信号中继（部分有/部分损坏，文档 02 §2）
```

**功能标志 `functions` 取值**（对齐文档 02 §7.4 / 03 §3）：

| 功能 | big_city | small_town | station | village |
|:--|:--:|:--:|:--:|:--:|
| trade（买/卖） | ✅ | ✅ | ✅(有限) | ✅(轻) |
| order（接单） | ✅ | ✅ | ❌ | ✅(轻) |
| rest（休息 50金,士气+1） | ✅ | ✅ | ✅ | ❌ |
| repair（修车） | ✅ | ❌ | ✅(偏修车) | ❌ |
| heal（医馆） | ✅(基础；激活后高级检疫) | ❌ | ❌ | ❌ |
| remodel（改造舱） | ✅(基础；激活后高级舱) | ❌ | ❌ | ❌ |
| activate_node（激活） | ✅(通关触发) | ❌ | ❌ | ❌ |
| recruit（招募） | ✅ | ✅ | ❌ | ✅(轻) |
| depart（出发） | ✅ | ✅ | ✅ | ✅ |

> 驿站"有限/偏修车"、村庄"轻"：实现时用小库存 / 少订单 / 不可讲价等轻量降级，不必另建子类，用 `functions` + 数量上限区分即可。

### 2.5 Order（订单）

```python
@dataclass
class Order:
    id: str
    type: str            # "deliver"（运 X 到 Y）/ "buy"（交 X 物给钱）
    goods: Goods
    qty: int
    to_loc: str          # 目的地 location id（deliver）
    deadline_day: int    # 截止天数（文档 04 §7：ceil(格距/2)×1.3，按 2 格/天）
    reward: int          # 报酬（⚠️ ≈预计消耗×1.5）
    publisher: str       # 发布者 NPC id（信任/讲价用）
    status: str = "active"   # "active" / "done" / "failed"
```

同时持单上限 3（文档 04 §7）。

### 2.11 Status（状态）

```python
@dataclass
class Status:
```

### 2.12 MapCell（格子）与 AshState（灰度）

```python
@dataclass
class MapCell:
    type: str            # 同 Location.type 的野外/障碍/地点基底
    ash_base: int = 0    # 地区基准灰度 0~100（固定，文档 03 §6 / 04 §8）
    explored: bool = False
    location_id: str = ""   # 若此格是地点，填 Location.id；否则空

@dataclass
class AshState:
    base: list = field(default_factory=list)     # 二维 [200][200] 地区基准灰度
    fluctuation: int = 0                          # 全局时间波动层（随机游走 ±20，文档 04 §8）
    def current(self, x, y) -> int:
        return min(100, self.base[y][x] + self.fluctuation)
```

> 探测仪显示 `current(x,y)`（基准+波动叠加），仅观测、非警报（文档 02 §6）。灰度影响：≥50 额外耐久磨损、≥70 感染风险、越高敌强/偶遇↑（文档 03 §6 / 04 §8）。

## 3. 类型约定小结

| 约定 | 用法 |
|:--|:--|
| 枚举 | 字符串常量（如 `"big_city"`、`"deliver"`），集中放 `config.py` 或模块顶部常量 |
| 坐标 | `(x, y)` 元组 |
| 数量 | 整数；食物/水用 `float`（小数消耗，显示四舍五入） |
| 列表容器 | `field(default_factory=list)` 避免可变默认参数陷阱 |
| 配置 vs 状态 | 固定数值进 `config.py`；玩家可变进 `Caravan` / `Character` 等实例 |
