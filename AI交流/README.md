### 🔴 三条硬规矩

**① Hermes 不许改 `游戏大纲\` 里的任何文件**
- 🔴 `0A_权威系统文档\` `A类文件附件\` `B类_开发文档\` —— **一律不许动**
- 🔴 **例外：`AI交流\` 可以写**（回执写在那里）
- 发现文档有问题 → 🔴 **写进 `AI交流\回复_HERMES_*.md` 说清楚，不要自己改**

**② 有疑问就停下问，不要自己挑一个方案**
> 真实案例：某份指令写「数值照抄 5A §2.3」，可那儿根本没这个数
> → AI 自己猜了一个 → **违反"不许自创"**
> 🔴 **停下问一句，比猜一个值省事得多。**

**③ 三份文档冲突时的优先级**
```
施工图（规则搬入 + 数据结构 + 主循环）
  ↓ 🔴 实施顺序以它为准
开发流程（🔴 唯一的执行顺序 · 5 刀垂直切片）
  ↓ 🔴 怎么验以它为准
测试用例（17 条 · 测的时候填结果）
```

> 🔴 **A 类是最终权威** —— B 类只是施工图，两者冲突时以 `0A_权威系统文档\` 为准。

### 🔴 2026-10-20 新增：开发记录机制

> 🔴 **目的**：🔴 让你**不用在三个 AI 的回执里翻哪份最新**，🔴 也不用逐行读代码判断进展。

| 谁 | 什么时候 | 干什么 |
|:--|:--|:--|
| 🔴 Hermes | 中阶段做完 | 写 `回复_HERMES_xxx.md` |
| 🔴 **WorkBuddy** | 🔴 **收到回执后** | 🔴 **核对代码 + 跑测试** → 追加 `开发记录.md` 一条 → 判定算不算做完 |
| 🔴 **你** | 🔴 **看到记录后** | 🔴 **人工验收** → 我把状态改成 ✅ |

🔴 **一条记录五项**：当前版本 · 实际完成内容 · 测试结果 · 待处理问题 · 下一步
🔴 **数字不许手打** —— 自动区由 `node 工具\开发记录.mjs` 生成（跑 git / vitest / tsc 取真值）
🔴 **验收状态只有两个**：`⏳ 待项目主验收` / `✅ 已验收` —— 🔴 没有"基本完成"这种中间态
