## §2 🔴 真的新增的三条半

### 2.1 🔴🔴 核心玩法循环（🔴 最重要的新增）

**讨论里的循环**：

```
1 定目标或旅行理由 → 2 备物资货物装备 → 3 选目的地与路线
  → 4 途中遇事件风险选择 → 5 抵达并完成贸易/探索
  → 6 获得资源财富能力信息机会 → 7 根据结果调整下轮计划
```

> 🔴 **🔴 A 类从来没有把它写成循环** —— 🔴 我 grep 过「核心循环 / 玩法循环 / 闭环」，🔴 **零命中**。
> 🔴 **A 类是「分系统写」的**（`1A` 写地图 · `2A` 写地点 · `10A` 写订单），
> 🔴 🔴 **但从没把它们串成一个循环**。

🔴 **为什么这条最重要**（讨论里自己的判断）：

> 「🔴 **核心玩法循环应当优先于大量细节系统的完善**」
> 「🔴 **在核心循环尚未明确之前，不宜急于把所有系统都实现完毕**」

🔴 **这句话跟我们现在做的事直接相关** —— 🔴 见 §5。

### 2.2 🔴 探索的成长循环 + Core Keeper 启发

**讨论里的循环**：探索新区域 → 获得资源装备知识 → 提升能力 → 进入更危险更复杂区域 → 继续探索

🔴 **借鉴《Core Keeper》的六点**（🔴 讨论里明确说「不代表需要照搬」）：

| 借鉴点 | 🔴 A 类有没有 |
|:--|:--|
| 探索发现资源 → 带回去升级装备 | 🔴 **半个**（`0A §四之五` 讲了熟悉地方有价值，🔴 没讲「升级后挑战更危险」） |
| 成长后重新探索先前危险区域 | 🔴 **没有** |
| 可长期采集的大型矿脉（减少重复寻找成本） | 🔴 **没有** |
| 大区域里发现小区域（意外与新鲜感） | 🔴 **没有** |
| 从敌人获得特殊装备 → 挑战更强敌人与 BOSS | 🔴 **没有** |
| 新区域提供不同资源、环境机制与挑战 | 🔴 **没有** |

> 🔴 **这几条是「探索为什么长期值得做」的机制答案** —— 🔴 🔴 **A 类讲了归属感（情感），没讲成长感（能力）**。

### 2.3 🔴 低成本原型方案

**讨论里的方案**：3–5 个地点 · 分岔路线 · 抽象表示补给车况钱币货物 · 走完「目标选择→准备→路线→事件→结算→下一步」

🔴 **验证重点五项**：能不能理解每个选择的意义 · 各路线是否有各自优势 · 有没有支配性最优解 · 一次旅程后有没有继续的理由 · 收益是否真的改变后续决策

> 🔴 **🔴 A 类没有原型验证方案** —— 🔴 而且 🔴 **我们现在做的 P1 其实就是一个更大的原型**（见 §5.2）。

### 2.4 半新增：事件分阶段

| 抵达时间 | 遇到什么 |
|:--|:--|
| 较早 | 起因与发展过程 |
| 较晚 | 已升级 / 转折 / 僵持 |
| 🔴 **很久以后** | 🔴 **事件已结束** —— 🔴 但**能从当地现状、人物经历、遗留物品、历史记录了解过去** |

> 🔴 **A 类确实没有** —— 🔴 它只说了「事实不强制玩家触发」，🔴 **没说「错过之后还剩什么」**。
> 🔴 **落到哪**：`5A` 事件表加一列「阶段」· `3B` 探索要能查「已结束事件的遗留」。

## §5 🔴🔴 这份东西对当前开发的影响（🔴 重点）

### 5.1 讨论里有一句话，跟我们现在做的事直接冲突

> 🔴 「🔴 **在核心循环尚未明确之前，不宜急于把所有系统都实现完毕**」

🔴 **我的判断**：🔴 **这句话对，但不该现在停手。** 理由：

| 理由 | 说明 |
|:--|:--|
| 🔴 **P1 不依赖核心循环** | 🔴 旅行基础（走一格 · 跨日 · 天气路况）🔴 **无论核心循环长什么样都要做** |
| 🔴 **但 P2 开始就依赖了** | 🔴 商队资源与地点服务 🔴 **要等「完成一趟能得到什么」定了** |
| 🔴 **P8 整合会返工** | 🔴 🔴 **如果核心循环变了，前七阶段的接口可能要改** |

> 🔴 **建议**：🔴 **P1 做完（P1~P1.4），🔴 进 P2 之前，花半小时把 §2.1 那个循环定下来。**
> 🔴 **不是现在停，是 P2 之前定。**

### 5.2 🔴 好消息：我们做的 P1 就是一个原型

🔴 讨论里 §2.3 提的原型方案是「3–5 地点 + 分岔路线 + 抽象资源」。
🔴 **我们现在做的比它大**：

| 讨论要的 | 我们有的 |
|:--|:--|
| 3–5 个地点 | 🔴 **107 个**（v0.7 地图实测） |
| 分岔路线 | 🔴 **570 格最短路 + 4 条备选** |
| 抽象补给车况钱币货物 | 🔴 抽象体力时间天气路况 |
| 走完一整轮 | 🔴 **正在做** |

🔴 **五个验证重点，我们已经覆盖三个**：

| 验证重点 | 现在的状态 |
|:--|:--|
| 能不能理解每个选择的意义 | 🔴 **需要你验收**（P1 第 5 步出验收表） |
| 各路线是否有各自优势 | 🔴 **要等路况加成定下来**（现在全是 0） |
| 有没有支配性最优解 | 🔴 ⚠️ 🔴 **现在就能答** —— 570 格走法唯一，🔴 **这就是「没有选择」** |
| 一次旅程后有没有继续的理由 | 🔴 **要等 P2**（那才有「赚到钱」） |
| 收益是否真的改变后续决策 | 🔴 **要等 P7** |

> 🔴 **🔴 第 3 条现在就有个真问题** —— 🔴 **P1 测出来的「570 格、178 天、平均每天 3.3 格」**
> 🔴 **就是「唯一走法」的表现** —— 🔴 **路线选择是 P1 不做的**，🔴 但 🔴 **这个结果本身说明「可选择」这件事在正式版必须补**。

## §6 🔴 三条要提醒的

### 6.1 「不要性格数值」🔴 建议立刻写进铁律

🔴 讨论里明确：「🔴 **不必依靠显式的善恶值或性格数值**」

> 🔴 **理由**：养成系统是这类游戏的默认引力 —— 🔴 一旦做了性格值，
> 🔴 玩家就会开始刷那个值，🔴 🔴 **成长就变成了刷数值**。
> 🔴 **A 类现在没有这条约束** —— 🔴 **这是新增**，🔴 🔴 **建议进 `铁律总纲.md`**（P3 前）。

### 6.2 🔴 `0A §四之五 §5` 末尾有个「待讨论」，这次正好接上

🔴 A 类原文：「经济、路线、任务该在多大程度上推动重访，而熟悉感与人物关系又该在多大程度上形成独立吸引力 —— **这一条还没定**」

🔴 **这次讨论的「三种动力」正好是它** —— 🔴 🔴 **A 类在那里等着被填**。

### 6.3 🔴 真缺口不是设计，是表现层

🔴 `0A §四之五 §2` 自己写着：🔴 **「`10A §1.6` 已有信任值，但信任涨了之后对方说什么、什么态度，文件里一个字都没写」**

🔴 **那才是要补的** —— 🔴 P3/P8。🔴 不是新建机制。
