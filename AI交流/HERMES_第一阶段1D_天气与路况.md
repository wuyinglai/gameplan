## 2. 🔴 本刀的意义（为什么天气和路况要一起做）

**每格消耗是全项目唯一的消耗出口。** 🔴 天气和路况都从这里出。

🔴 **为什么必须一起做完再测**：
- 只做完天气 → 玩家还是只有一种走法，🔴 那不叫旅行叫赶路
- 只做完路况 → 天气还是恒定晴天，🔴 天气段白做
- 🔴 **两者的叠加（1D-3）才是真正要验的东西** —— 暴雨 +5 叠恶劣路况 +10 = 每格 30，是基础 15 的两倍。🔴 **只分开测，永远发现不了叠加重复计算。**

## 5. 1D-3 组合测试 + 🔴 你那三条建议的落地

### 要做

**① 组合叠加**
| # | 场景 | 预期 |
|:-:|:--|:--|
| 1 | 晴朗 + 好路 | 每格 **15** |
| 2 | 暴雨 + 好路 | 每格 **20** |
| 3 | 晴朗 + 差路 | 每格 **20** |
| 4 | 🔴 **暴雨 + 差路** | 每格 **25**（15+5+5） |
| 5 | 🔴 **灰烬风暴 + 差路** | 每格 **30**（15+10+5） |

🔴 **第 4、5 行是本刀最重要的两条** —— 🔴 **加成重复计算（加了两次）只有这两行能抓到。**

🔴 **每格消耗必须只有一个出口** —— ❌ 不许天气模块、体力模块、主循环各自加一遍。

**② 改名 `开新的一天()` → `今天还在继续()`**（`结算.ts`）

理由：🔴 **它恰恰是在「没跨日」的时候调用的**，名字却像"新的一天开始了"。🔴 将来有人把它挪进 `跨日()` 里（那里先置 `true` 再被清 `false`），幂等就永远失效。
🔴 改完在文件头注释里写明：**「推进了时间 = 这一天还在继续，所以清掉今日结算标记」**。

**③ 复位改挂 `时间.推进()`**（采纳你的方案 a）

🔴 **理由**：现在复位只挂在主循环两个入口，🔴 将来加「等待 / 扎营 / 侦察」这类耗时动作，谁忘了调它，跨日之后那一天又会「结束当天」用不了 —— 🔴 **就是你这次修掉的死锁的原版复发**。而"哪个动作耗时"是**每个新动作都要重复回答一次**的问题，🔴 挂在 `时间.推进()` 里是回答一次就永久正确。

**改法**：把 `状态.今天已结算 = false` 挪进 `时间.ts` 的 `推进()`。
🔴 **前提**：`推进()` **不许碰 `第几天`** —— 🔴 一碰就出现了第二个跨日入口，`跨日()` 的唯一性就没了。
🔴 改完**必须删掉** `结算.ts` 里那个 `开新的一天()` 导出函数 —— 🔴 留着就等于留了第二个能重置跨日状态的地方。

**④ 补一条断言**：走一格 → 跨日 → **直接调「结束当天」** → 🔴 **必须被拒绝**（今天已结算过）。
