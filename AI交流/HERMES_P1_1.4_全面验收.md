## 3. 🔴 长时间稳定性（本步的重点）

### 3.1 连跑 30 天

```
起点 (10,199) → 连续走 30 天（体力不够就「结束当天」）
```

| 检查 | 期望 |
|:--|:--|
| 🔴 跨日次数 | **正好 30 次** —— 🔴 一次不多一次不少 |
| 🔴 `第几天` | 从 1 变成 **31** |
| 🔴 `当前小时` | 永远是 **7 / 9 / 11 / 13 / 15 / 17** 之一 —— 🔴 **不许出现 19** |
| 🔴 `野外体力` | 🔴 **永远在 0 ~ 100 之间** —— 🔴 **不许负数、不许超上限** |
| 🔴 天气段 | 🔴 剩余天数永远 ≥ 1 —— 🔴 **不许出现 0 或负数** |
| 🔴 走过的格数 | ≈ 30 × 3 = **90 格左右** |

### 3.2 往返测试

```
从起点走到某个地方，再原路走回来
```
🔴 **检查**：回来时体力 / 时间 / 天数都对得上，🔴 **没有残留状态**。

### 3.3 边界连续打

| 场景 | 期望 |
|:--|:--|
| 🔴 体力只剩 5 点时反复点「走一格」10 次 | 🔴 **10 次全被拒**，🔴 状态一点不变 |
| 🔴 17:00 反复点 10 次 | 🔴 **第一次成功后**，🔴 后 9 次全被拒（时间不够） |
| 🔴 刚跨过日立刻点「结束当天」10 次 | 🔴 **全部被拒** —— 🔴 **一天只跨一次** |

## 5. 🔴 出中文验收表（🔴 本步的主要产出）

🔴 **严格按 `AI交流\HERMES_阶段验收脚本规范.md` 的格式。**

### 5.1 表的结构

| 列 | 内容 |
|:--|:--|
| **项目** | 测的是哪一条 |
| **预期** | 具体数字（🔴 不许写「正常」「正确」） |
| **实际** | 跑出来的数字 |
| **对不对** | ✅ / ❌ / ⏳ 待裁定 |

### 5.2 🔴 三条格式硬要求

| # | 要求 | 违反后果 |
|:-:|:--|:--|
| 1 | 🔴 **每种天气必须逐个列一行**（12 行） | 🔴 合并成「天气都能改变消耗」🔴 **等于没测** |
| 2 | 🔴 **每行用全新状态** | 🔴 同一份状态先暴雨再改晴朗 🔴 **结果不可信** |
| 3 | 🔴 **表尾写零回归** | 🔴 前四步的判据必须仍全过 |

### 5.3 🔴 允许「不合格」的行

| 情况 | 怎么写 |
|:--|:--|
| 🔴 加成待裁定 | `⏳ 待裁定` + 写清缺什么 |
| 🔴 设计问题（不是 bug） | ❌ + 写清「这是 A 类规则的结果，🔴 待项目主裁定」 |

> 🔴 **🔴 宁可表里有 5 行 ⏳，🔴 也不许全 ✅** —— 🔴 **全绿往往意味着没测。**
