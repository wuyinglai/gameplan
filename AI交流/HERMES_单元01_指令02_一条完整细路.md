【要做】
1. 建 7 个模块（§3.6）：
   地图.ts（已有）· 时间.ts · 体力.ts · 每格消耗.ts · 结算.ts · 结束当天.ts · 主循环.ts

2. 每格消耗.ts —— 🔴 全项目只有这一个函数算「走一格扣多少」
   export function 每格消耗(状态, 目标格): number {
     return 15 + 天气每格加成[状态.当前天气] + 路况每格加成[目标格.路况档];
   }
   🔴 本刀先把天气和路况都按 0 算，恒返回 15（阶段③④才分别接上）
   🔴 天气模块以外的人不许自己判断加成

3. 时间.ts —— 🔴 只做两件事：推进动作耗时、报告是否到日界
   🔴 【不许改 第几天 / 当前小时】—— 那是 结算.跨日() 的事

4. 结算.ts —— 🔴 唯一的跨日入口 跨日(状态)
   做四件事，一次不多一次不少：
     状态.第几天 += 1
     状态.当前小时 = 7
     状态.野外体力 = min(100, 体力 + 50)
     天气段 -1（到期重掷）
   🔴 【绝对不许】主循环里也回一次体力 —— 那是本单元最容易出的 bug

5. 结束当天.ts —— 🔴 独立操作，不碰移动
   结束当天(状态) → 只调 结算.跨日()
   🔴 不许改坐标 · 不许扣移动体力 · 不许额外推进 2 小时
   🔴 幂等：已经是第2天07:00（刚跨过日）→ 不可用

6. 主循环.ts —— 🔴 严格照 §3.8 的九步，一步不许调换：
   ① 目标坐标在范围内吗？    否→拒绝，什么都不扣
   ② 与当前格相邻吗？（四方向）否→拒绝
   ③ 🔴 目标格可通行吗？（山/水不可进）否→拒绝
   ④ 体力够吗？（调 每格消耗()） 否→拒绝
   ⑤ 🔴 剩余时间够跑完这一整格吗？否→拒绝（不许做一半）
   ⑥ 全过→执行：扣体力 → 时间+2h → 换坐标
   ⑦ 时间到 19 点了吗？ 否→回到 ①
   ⑧ 🔴 是→立刻调 结算.跨日()（只调一次）
   ⑨ 走进没到访过的地点 → 标记 已到访 = true

【🔴 完成后必须断言（数字不许改）】
场景 A · 半天收工：
  体力 100 → 走 3 格 → 剩 55 → 主动「结束当天」→ 55+50=105 【被上限封顶为 100】
  → 第 2 天 07:00，体力 100

场景 B · 走满一天：
  体力 100 → 一路走到第 6 格（19:00 自动跨日）→ 跨日前剩 10
  → 10+50 = 【60，不是 100】→ 第 2 天 07:00，体力 60

边界：
  · 体力 10 时走一格 → 拒绝，体力/时间/坐标全不变
  · 18:00 走一格 → 拒绝（要 2 小时但只剩 1 小时），什么都不扣
  · 走山 / 走水 → 拒绝
  · 🔴 只调「推进 2 小时」20 次 → 【第 4 天 11:00】（跨日 3 次）
  · 🔴 只调「推进 2 小时」6 次 → 第 2 天 07:00（跨日 1 次）
  · 🔴 15:00 且体力 0 时「结束当天」→ 日期 +1、时钟 07:00、坐标不变
  · 🔴 19:00 已自动跨日后再调「结束当天」→ 【不能再跨一次】（幂等）

【🔴 跨日只发生一次】
必须能断言：同一次到达 19:00 → 日期+1 一次 · 时钟重置一次 · 体力回一次 · 天气段推进一次
任何一处出现两次就是重复结算。
