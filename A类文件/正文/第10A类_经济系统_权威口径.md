## 一、交易与讲价系统

本系统借鉴"商人视角游戏"的核心乐趣——**做生意本身就是目的，不是手段**。讲价机制从已有系统自然长出，不凭空加设定。

### 1.1 交易场景

商队在各类地点（城市 / 城镇 / 小城 / 驿站 / 村庄）可与固定商人 NPC 发生三类交易：

| 场景 | 行为 | 讲价方向 |
|:----|:----|:----|
| 买 | 购入货物 / 装备 / 补给 | 压低成交价 |
| 卖 | 出售货物 / 旧装备 | 抬高成交价 |
| 接订单 | 与订单发布者谈酬金 | 抬高委托酬金（"这趟风险大，加钱我才接"） |

标价为**城市基准价**（🔴 价格的家 = **`第2A类 §7`**，不在本文件），讲价围绕基准价上下浮动。

### 1.2 讲价触发

- **大单 / 订单**：默认进入谈判界面。
- **小单**：按默认价直接成交；玩家**主动按键**才进入讲价。
- 自然过渡：前期资金紧张，玩家会为省几块主动讲价攒钱买装备；后期宽裕后往往直接按默认价买，不再耗时间讲小单。

### 1.3 讲价执行者

- 队伍中有 **"账房 / 商人"特质的特殊人员**（定义见第6A类）→ 讲价加成：成交空间更大、对方更易接受。
- **无特质（队长自己谈）** → 也能讲，但成功率降低、对方底线更硬（压不到那么低 / 卖不到那么高）。
- 不强制要求特定职业在场，但有无对应人员会造成明显差异。

### 1.4 核心机制：5 轮拉锯 + 读态度

每个固定商人 NPC 隐藏三条线，玩家不可直接读取数值：

| 隐藏线 | 含义 |
|:----|:----|
| 成本底价 | 他的成本线，低于此他不卖 / 不买 |
| 满意价 | 他心理舒服的成交价 |
| 急迫度 | 他多想做成这单（库存积压 / 急需某货 / 月底交差等） |

玩家出价 → NPC 给出**态度反馈（不显示数字）** → 可拉锯最多 **5 轮**，越谈越能摸透对方价位区间：

- 他皱眉 → 你压太低 / 抬太高
- 他眼神亮了 → 这价他赚到了
- 他叹气说"今年灰重货紧" → 暗示稀缺、底线硬

第 5 轮或玩家主动喊停时定结果：成交 / 妥协价成交 / 暂不成交。

### 1.5 影响成败的变量

讲价结果由以下因素共同决定（均从已有设定长出，不新增独立系统）：

1. **讲价者特质**：有"账房 / 商人"特质 → 加成。
2. **宏观声望**：商会城市分会声望（见第7A类）。声望高 → 该城分会提供更好价格与订单条件。
3. **个体信任**：具体 NPC 的信任值（见 1.6）。
4. **城市态度（仅统治层政策，见 1.7）**：影响关税与官方门槛，不裁定普通 NPC。
5. **灰度**：高灰烬区物资稀缺 → 卖家抬价、玩家反而能高价出货。
6. **急需度**：你带去的货正是对方紧缺的 → 他更松口。

### 1.6 声望与个体信任（三层）

- **世界声望（全局）**：跨城可见的**公开名声**，放在所有城市都算数。遭遇其他商队时**对方能看到它**（见第7A类「路上遇到的人」）；动手打人被发现会掉，**剿灭有悬赏的劫道者会涨**。
- **宏观声望（城市分会级）**：沿用第7A类设定。玩家是余烬商会流动分会，在某城分会声望高 → 该城提供更好价格与专属订单。
- **个体信任（NPC 级）**：每个固定商人 NPC **有名字、有信任值**。
  - 公平成交、不欺诈 → 信任升；
  - 狠宰 / 骗 → 信任降。
  - 信任高了 → 给暗折扣、留好货、甚至**透露灰烬区情报**（接"世界活着"与灰度系统）。
- **通缉标记**：被某城悬赏的公开状态，遭遇时可见。它有两面——**对方被通缉 = 打他合法、无恶名、还能领赏**；**自己被通缉 = 谁都不怕先动手打你，且赏金猎人会上门**（见第7A类 §五 / §六）。
- 这几层叠加，是把"稀疏的生机"变成温度的方式——路上难得遇个熟人，处好关系就是孤旅里的温暖点。

#### 🔴 1.6.1 🔴 信任的表现层（**信任涨了之后对方说什么、什么态度**）

> 🔴 **2026-10-23 补** —— 🔴 `0A §四之五 §2` 指出：「`10A §1.6` 已有信任值，🔴 **但信任涨了之后对方说什么、什么态度，文件里一个字都没写**」。

| 信任档 | 对方的态度 | 🔴 **具体表现（至少一种）** |

| 🔴 **面熟** | 认得你 | 🔴 一句问候 · 报出你的商队名 |
| 🔴 **熟客** | 惦记你 | 🔴 主动留好货 · 告诉你哪里不太对劲 |
| 🔴 **自己人** | 站在你这边 | 🔴 透露灰烬区情报 · 危险时出价更低 · 替你说话 |

| 🔴 三条不能破 | 说明 |
|:--|:--|
| 1 | 🔴 **不需要所有人都有庞大记忆** —— 🔴 **只要在"合适的时候"让玩家感觉到"我过去的经历没有完全消失"** | 🔴 `0A §四之五 §2` 原话 |
| 2 | 🔴 **表现层不许变成数值面板** —— 🔴 **要靠对话与态度，不靠弹窗写"信任 +5"** | 🔴 **性格数值 / 养成系统是这类游戏的默认引力**（`0A设计思路 §八`） |
| 3 | 🔴 **态度变化必须与那段经历相符** —— 🔴 **帮过他 → 再遇时他记着；被他骗过 → 他也不记着** | 🔴 🔴 **"世界记得玩家"的核心** |

> 🔴 **具体台词与选项写法 → 属 `5A` 事件内容**，🔴 **本节只定"档位 → 态度 → 表现方向"**。
> 🔴 **完整口径（两种记忆 / 日常与深刻事件共存 / 世界记忆只做三层）→ `0A §四之五`**。

### 1.7 城市态度的修正口径（重要）

**城市态度仅指统治阶层的官方政策**：
- 城市的"态度"**仅指其统治阶层 / 城主 / 主流势力对商队的官方政策态度**，作用范围限于**政策与权贵层面**：关税高低、能否自由进城、城主是否故意刁难、城里大势力是否针对你。
- **普通 NPC 拥有完全独立的立场**，不随城市态度被裁定。
- 因此：敌对城（枯林 / 海盐 / 灰烬）的铁匠可能乐意帮你修车；友善城（粮野 / 黑石）也有想坑你钱的奸商。
- 🔴 **本口径同样适用于城市交互的全部场景**（`第2A类`）—— 🔴 **第9A类城市系统不建**（用户裁定：城市交互已由 `第2A类` 覆盖，宏观城市系统与孤旅调性冲突），城市差异主要通过统治层政策（关税 / 准入）体现，**而非全员立场**。

### 1.8 谈崩处理与竞争者窗口（防刷）

- **谈崩 ≠ 绝交**：可以妥协到一个双方都接受的价格成交；也可以改日再来，他**不涨价**继续谈。
- **竞争者时间窗口（防无限拉锯）**：
  - **稀缺物资 + 订单**：有窗口，约 **1~2 周（游戏内时间）**，玩家磨蹭会被世界上**别的商队买走 / 接走**，该单消失。
  - **普通物资**：**不设窗口**，满世界都是不值得抢，玩家可随意讲价。
- 此机制既防止无限拉锯，又让"世界在运转"——别的商队也在活动、抢机会。

## 二、订单系统

> 🔴 **本节是订单的家** —— 分档 / 报酬公式 / 类型 / 时效 / 违约 / 接单规则，**全部写在这里**，别处只引用。
> ⚠️ **数值口径**：移动基准 = **3 格/天**（`第1A类 §2.2`）；🔴 **本节的 `H_档` / `k_档` / `k_期` 只是推导用的参考值**，最终数值走 **`23` 数值推导规则** / **`24` 执行器**，**不在本文件手改**。

### 2.1 订单从哪来 · 怎么流转（**玩家视角的完整流程**）

```
① 在城里看到订单       ← 市场 / 商会分会 / 悬赏板 / 城主·领主 / 个人 NPC / 酒馆
        ↓
② 决定接不接（讲价可抬酬金，见 §一）
        ↓
③ 接单 → 货物/人/目标 装车（占车厢格，见 `第3A类 §3`）
        ↓
④ 出发上路（🔴 订单只给起点+终点，怎么走玩家自己定）
        ↓
⑤ 路上：可顺路接别的单 / 探索 / 卖货（🔴 期限是"里程预算"，不是死线）
        ↓
⑥ 到终点交付 → 按 §2.7 判结果（早到 / 准时 / 延期 / 严重超期）
        ↓
⑦ 领报酬（+ 或 − 声望）
```

- 🔴 **同时持单无上限** —— **为什么**：A→B 路上有 C 点，去 C 的单和去 B 的单顺路，就该一起接、顺路做，路上还能卖货。**多接顺路单正是赚钱方法**，不该禁。
- 🔴 **好消息：订好货 ≠ 一定要按时到**（见 2.7）。

### 2.2 四档划分（**按路程，不按客户要求**）

> 🔴 **移动基准 3 格/天** → **天数 × 3 = 格数**（`第1A类 §2.2`）

| 档位 | 天数 | 对应格数 | 典型阶段 |
|:--|:--:|:--:|:--:|
| **短途** | **≤ 60 天** | ≤ 180 格 | 初期 |
| **中途** | 60 ~ 120 天 | 180 ~ 360 格 | 初期 → 中期过渡 |
| **长途** | 120 ~ 200 天 | 360 ~ 600 格 | 中期 |
| **超长途** | **≥ 200 天** | ≥ 600 格 | 后期 |

- 🔴 **超长途有上限**（600 格 / 200 天）—— 不是无限单。
- **期限** = **路程天数 × `k_期`**（短 2.0 / 中 2.1 / 长 2.2 / 超长 2.3 · ⚠️ 参考值，归 `23`）。
- 🔴 **期限 = 里程预算，不是限时死线**（2026-09-24 用户定）：**订单只规划路线** —— 怎么走、绕不绕、停不停，玩家自己决定。

### 2.3 报酬怎么算（**主式**）

```text
订单报酬 = H_档 × 路程天数 × k_档

k_档（倍率，逐档递增 · 超长途单独拔高）：
  短途 2.4  ｜  中途 2.7  ｜  长途 3.0  ｜  超长途 3.6
```

| 档位 | `k_档` | 净利润率（走最短 · 全额拿 · 上限口径） |
|:--|:--:|:--:|
| 短途 | 2.4 | 约 140% |
| 中途 | 2.7 | 约 170% |
| 长途 | 3.0 | 约 200% |
| 超长途 | 3.6 | 约 260% |

- **`H_档` = 该档应有规模的日均硬账**（⚠️ 参考值 300 / 934 / 1,493 / 1,493，**归 `23`**）。
- **倍率是中心值，不是固定值** —— 实际发放时在该倍率上下浮动（⚠️ ±5%，待实测）。
- 🔴 **"净利润率"是上限口径**（走最短路径、不在路上多待）；**期限给足后玩家通常会"在路上多待"** → 实际净利向下走。
- 🔴 **报酬可以谈**（接单时抬酬金，见 `§一` 讲价）—— 谈成了就是你的。

### 2.4 订单类型（**4 大类**）

| 类型 | 内容 | 时效 | 🔴 需要接取？ | 失败条件 |
|:--|:--|:--:|:--:|:--|
| **送货** | 把货物运到指定收货地 | **有期限** | ✅ **需要** | 严重超时 → 失败 |
| **护送** | 护送某人 / 某物到指定城市 | **有期限** | ✅ **需要** | 严重超时 → 失败 |
| **收购** | 高价收购指定物品（城市 / 个人发布） | **无期限** | ❌ **不用接** | 无 —— 交货就给钱 |
| **悬赏** | 击杀指定敌人 / Boss | **无期限** | ❌ **不用接** | 无 |

- **来源**：市场 / 商会 / 悬赏板 / 领主·城主 / 个人 NPC / 酒馆。
- 🔴 **收购、悬赏不用专门接** —— 带着货到了直接交、杀了目标拿凭证直接领，**世界更活**。
- 🔴 **收购 / 悬赏有随机时限**：**被别的商队 / 赏金猎人完成了就消失** —— 世界在运转，别人也在抢。

### 2.5 难度分级

| 难度 | 说明 |
|:--|:--|
| **很简单 / 简单 / 正常 / 困难 / 很困难** | 越难 → **刷新率越低 · 奖励越高 · 被 NPC 抢走得越慢** |

### 2.6 接单规则与刷新

| 项 | 规则 |
|:--|:--|
| **同时持单** | 🔴 **无上限**（理由见 2.1） |
| **期限** | 路程天数 × `k_期`（见 2.2）· 🔴 **里程预算不是死线** |
| **讲价抬酬** | 接单时可谈判提高酬金（`§一`） |
| **刷新** | **每天随机刷新**，各类型概率 ⚠️ 待定 |
| **竞争者窗口** | 好订单约**1~2 周（游戏内）**会被别的商队接走（`§一 1.8`） |

### 2.7 交付结果与违约（**四种结局**）

| 交付情况 | 结果 |
|:--|:--|
| **早到** | 🔴 **额外声望奖励**（可能还有小额奖金 ⚠️ 待定） |
| **正常时间到** | 无额外奖励、无惩罚，**按约定付酬** |
| **延期**（超期但可补救） | **声望损失 + 佣金减少**（还是给钱，只是少给） |
| **严重超期** | **大量声望损失 + 不支付报酬** → **订单失败** |

- 🔴 **货物被毁不算订单失败**，只损失货物本身（不扣报酬 —— 那是 `第3A类 §5.2` 的货损，另一件事）。
- 🔴 **延期不是失败** —— 铁律："**迟到 ≠ 失败**"。延期照样拿钱（少拿），只有严重超期才黄。
- **收购 / 悬赏** 无接取，不存在失败，只可能**被别人完成而消失**。
- 🔴 **货损 ≥70% → 订单直接失败**（见 `第5A类 §7.3`）。

### 2.8 🔴 一条贯穿全局的红线

> 🔴 **订单只定起点和终点，怎么走玩家自己定。**
>
> 期限给得足（≥ 最短路程 × 2），所以**绕路、停驻、探索都不亏**（`第0A类 §三`）。**订单不是"限时打卡任务"，是"一段路的委托"。**

## 三、跨城物价与跑商

> 核心结论（🔴 细则原挂在 `90_历史与废案/25_Demo计划_已废案_20261024/14`，**已按废案管理**）：
> - **每城一套价**（🔴 **物价三档口径见 `第2A类 §1.3`** —— 一档：大城 · 小城 → 二档：城镇 · 驿站 → 三档：村庄最贵；有特产的城把该货调低）；**每日三角分布波动**（一般货±20%、战略资源±10%）。

## 4.1 系统定位


产业经营是商队经营玩法的延伸。玩家在发展到一定阶段后，可以在城市中购买土地、矿区或其他产业设施，建立属于自己的产业，通过雇佣人员进行生产，获得稳定的资源与收入。

本系统不是游戏的主要玩法，不以复杂的经营管理为核心，而是为玩家提供长期资产、稳定资源来源，以及参与城市经济和影响世界发展的机会。

### 设计原则

| # | 原则 |
|:-:|:--|
| 1 | 🔴 **产业经营应当相对简单**，不应发展成复杂的模拟经营游戏。 |
| 2 | 🔴 **产业能够持续生产**，但不应替代玩家的探索、贸易和世界互动。 |
| 3 | 🔴 **已经成熟的重复性事务可以自动运作**，减少玩家不必要的操作。 |
| 4 | 🔴 **玩家仍然需要亲自探索新的地区、发现新的市场、建立新的产业和解决新的问题。** |
| 5 | 🔴 **产业经营应当与城市经济、市场供需、居民生活和世界变化产生联系。** |
| 6 | 🔴 **机制应当尽量精简**，不为产业经营额外增加大量低价值的管理操作。 |

> 🔴 **这六条与 `第0A类_设计思路` 的对应关系**：
> 🔴 **原则 1 与 6** → `§十二 机制精简`（🔴 审查六问）
> 🔴 **原则 3** → `§十一 拒绝无意义的时间消耗与重复劳动`（🔴 **本系统是这条理念的最大受益者**）
> 🔴 **原则 2 与 4** → `§九 双核心体验`（🔴 **经营不能压倒探索**）

## 4.2 产业所有权与城市关系


玩家购买的产业属于玩家的完全私有财产。

产业包括但不限于：

- 农田及种植用地。
- 矿区及矿产开采设施。
- 工坊及相关生产设施。
- 商会经营场所。

城市不能因为普通的经营变化或单纯的政策调整，就随意收回玩家的私人产业。

但是，私人财产不代表玩家可以不受限制地影响城市。

玩家的产业经营行为会影响城市经济、居民生活和当地社会关系。如果玩家严重损害城市居民利益，可能引发居民不满、社会冲突和城市管理者的反对。

例如，玩家利用自己掌握的大量粮食供应，恶意囤积粮食并大幅抬高价格，导致居民难以购买基本粮食，可能激起民愤。

当矛盾严重到一定程度时，城市可能采取强制措施，最终将玩家彻底驱逐出城。

### 🔴 需要区分的三件事

| # | 事项 |
|:-:|:--|
| 1 | 🔴 **产业所有权属于玩家。** |
| 2 | 🔴 **玩家在城市中的经营和活动会受到社会环境影响。** |
| 3 | 🔴 **严重破坏城市利益可能导致玩家失去在该城市继续经营和活动的资格。** |

🔴 **城市驱逐属于严重后果**，不应因普通价格波动或正常市场竞争轻易触发。
> 🔴 **🔴 归口（待定）→ `§七 7.2` 第 6 条** —— 🔴 **它跟 `第7A类 §六` 的「声望 + 通缉」是什么关系，待裁定**。

## 4.3 产业类型

### 4.3.1 农业产业

玩家可以购买农田或种植用地，雇佣工人后生产粮食、药材及其他农作物。

**可能的产业类型**：

| 类型 | 产出 |
|:--|:--|
| 🔴 **普通农田** | 粮食 |
| 🔴 **药材种植地** | 常见药材 |
| 🔴 **特殊种植地** | 特定地区的特色植物 |

**主要机制**：

| # | 机制 | 作用 |
|:-:|:--|:--|
| 1 | 🔴 **土地规模** | 决定基础种植能力 |
| 2 | 🔴 **土地肥力** | 影响产量，长期种植可能降低肥力 |
| 3 | 🔴 **雇佣人员** | 决定土地能否正常运作及生产效率 |
| 4 | 🔴 **生产周期** | 不同作物具有不同的生产周期 |

🔴 **玩家选择种植作物并安排人员后，产业按照生产周期自动结算产量**，不要求玩家亲自执行日常种植和收割操作。

### 4.3.2 矿产产业

玩家可以购买矿区或取得矿产区域的开采资产，雇佣人员后持续开采矿石。

**主要机制**：

| # | 机制 | 作用 |
|:-:|:--|:--|
| 1 | 🔴 **矿区储量** | 决定矿区能够持续生产多久 |
| 2 | 🔴 **开采效率** | 影响单位时间内的产量 |
| 3 | 🔴 **雇佣人员** | 决定矿区的生产能力 |
| 4 | 🔴 **开采周期** | 决定产出结算频率 |

🔴 **矿区可以持续产出矿石，但不是无限资源。** 随着开采进行，矿产储量逐渐减少，最终可能枯竭。

🔴 **不同地区可以拥有不同矿产资源**，玩家需要通过探索发现新的矿区。

### 4.3.3 工坊产业

工坊负责将原材料加工成其他商品。

**例如**：粮食 → 食品 · 原矿 → 金属材料 · 药材 → 药品 · 木材 → 建筑材料。

**主要机制**：

| # | 机制 |
|:-:|:--|
| 1 | 🔴 **选择生产项目** |
| 2 | 🔴 **提供必要的原材料** |
| 3 | 🔴 **雇佣工人** |
| 4 | 🔴 **按照生产周期结算产出** |

🔴 **工坊不采用复杂的机器摆放、生产线布局和工人岗位分配机制。** 玩家只需要选择生产项目并提供必要条件，工坊即可自动运作。

🔴 **不同工坊可以拥有不同的生产项目和原材料需求，使产业之间产生联系。**

### 4.3.4 商会经营场所

玩家可以在城市中购买或建设商会驻地，建立自己的商业组织。

**商会的基础定位**：

| # | 定位 |
|:-:|:--|
| 1 | 🔴 作为玩家在城市中的**长期经营据点** |
| 2 | 🔴 作为玩家**产业、仓储和贸易活动的组织中心** |
| 3 | 🔴 为玩家与其他商队合作、扩大贸易网络提供基础 |
| 4 | 🔴 **代表玩家在当地拥有一定的商业身份和影响力** |

🔴 **商会初期不需要复杂的职位、权限树和成员管理机制。** 其具体功能应当围绕产业经营和贸易合作展开。

> 🔴 **商会的详细运作（招募受雇商队 · 贸易委托）→ 本文件 `§五`**。

## 4.4 产业生产与雇佣人员


不同产业尽量采用统一的基础运作逻辑。

**玩家购买产业后，需要雇佣人员，产业才能正常生产。**

**产业主要关注以下条件**：

| # | 条件 | 作用 |
|:-:|:--|:--|
| 1 | 🔴 **产业规模** | 决定基础生产能力 |
| 2 | 🔴 **雇佣人员** | 决定产业能否运作及生产效率 |
| 3 | 🔴 **生产条件** | 根据产业类型，可能涉及土地肥力、矿产储量或原材料供应 |
| 4 | 🔴 **生产周期** | 决定多久结算一次产出 |

🔴 **产业运行后，系统按照生产周期自动结算产量，并将产物存入玩家的仓库。**

**不同产业只保留必要的特殊限制**：

| 产业 | 特殊限制 |
|:--|:--|
| 🔴 农田 | 土地肥力、种植周期 |
| 🔴 矿区 | 矿产储量、开采效率 |
| 🔴 工坊 | 原材料、生产效率 |
| 🔴 商会 | 经营规模、合作关系 |

🔴 **不为所有产业统一添加设备耐久、工人疲劳、随机故障、每日维护等机制**，除非后续证明这些机制能够创造必要的玩法价值。

> 🔴 **这一条与 `第0A类_设计思路 §十二 机制精简` 完全一致** —— 🔴 **「统一添加」本身就是要避免的**。
> 🔴 **🔴 雇员归属（待定）→ `§七 7.2` 第 3 条** —— 🔴 **产业雇员算不算玩家车队的人，🔴 碰铁律 21**。

## 4.5 商品储存与市场交易


产业产出的商品属于玩家，原则上不应直接自动兑换成金币。

**玩家可以自行决定如何处理商品**：

| # | 处置方式 |
|:-:|:--|
| 1 | 🔴 出售给当地市场，获得金币 |
| 2 | 🔴 存入仓库，等待价格变化 |
| 3 | 🔴 运往其他城市，利用地区间的价格差异获利 |
| 4 | 🔴 用于商队补给 |
| 5 | 🔴 交给工坊作为加工原料 |
| 6 | 🔴 用于订单或其他经营活动 |

### 4.5.1 商品价格

商品价格受到当地供需关系影响。

**可能的影响因素**：

- 当地生产量。
- 当地商品需求。
- 城市人口规模。
- 灾害和特殊事件。
- 外部贸易和商品流入。
- 其他商人及当地生产者的经营行为。

**例如**：

- 城市粮食丰收，供应增加，粮价可能下降。
- 城市发生灾害，粮食供应减少，粮价可能上涨。
- 城市人口增长，粮食需求增加。
- 贸易路线中断，外来商品减少。

> 🔴 **🔴 与本文件 `§三 跨城物价与跑商` 的关系** —— 🔴 **§三 定了「每城一套价 · 每日三角分布波动」**，🔴 **本节说的是「供需影响价格」**。
> 🔴 **🔴 两套模型怎么合 → `§七 7.2` 第 1 条**（🔴 倾向：供需驱动为主，三角分布降为兜底）。

### 4.5.2 商品囤积与出售

玩家可以将生产所得存入仓库，不必立即出售。

玩家可以观察市场变化，在价格较低时储存商品，在需求增加、供应减少或价格上涨时出售。

🔴 **仓储可以具有容量限制。** 对于容易腐坏的商品，可以设置储存损耗；金属矿石等不易腐坏的商品则可以长期保存。
> 🔴 **🔴 仓储容量与玩家货舱的关系（待定）→ `§七 7.2`** —— 🔴 **产业仓库与 `第3A类` 的车厢容量是不是两套**。

🔴 **不必让所有商品都具有腐坏机制。**

### 4.5.3 城市之间的价格差异

不同城市可以拥有不同的资源条件、生产能力和商品需求。

**例如**：

- A 城市粮食丰富，价格较低。
- B 城市粮食短缺，价格较高。

**玩家可以在 A 城市购买或生产粮食，再运输到 B 城市出售。**

**也可以直接在 B 城市建设农田，减少运输成本。**

🔴 **产业提供稳定生产来源，商队负责将商品带入更广阔的市场。两者应当互相支持，而不是互相替代。**

> 🔴 **这一条与 `第0A类_设计思路 §九 双核心体验` 同源** —— 🔴 **「商队把产业商品带进更广阔的市场」正是「两者相互支持」的落地**。

## 4.6 产业与城市经济的互动


玩家拥有的产业可以对城市经济产生实际影响。

例如，玩家拥有城市内大量农田，成为当地重要的粮食供应者，那么玩家增加或减少粮食产量，就可能影响当地粮食供应和市场价格。

玩家的影响力与其产业规模、市场份额以及其他供应渠道有关。

**但玩家不能完全控制市场。**

### 4.6.1 其他供应者

城市中还可能存在当地农户、其他商人和外地贸易商。

玩家占据的市场份额越高，对价格和供应的影响越大；但其他供应者仍然可以提供商品，限制玩家的控制能力。

### 4.6.2 外部贸易

如果某种商品在当地价格过高，外地商人可能会将商品运入该城市。

外部贸易可以增加市场供应，限制玩家通过囤积商品无限抬高价格的能力。

### 4.6.3 居民与城市反应

玩家的经营行为会影响居民生活和城市态度。

| 行为 | 后果 |
|:--|:--|
| 🔴 长期稳定供应粮食 | 可能改善当地居民生活并提升玩家的商业声誉 |
| 🔴 恶意囤积粮食并大幅抬价 | 可能导致居民不满 |
| 🔴 长期制造严重的商品短缺 | 可能引发社会冲突 |
| 🔴 严重损害城市居民利益 | 可能导致城市管理者采取强制措施 |

🔴 **极端情况下，玩家可能被彻底驱逐出城市**，失去在当地继续经营和活动的资格。

🔴 **城市也不是完全被动的。** 它可以通过引进外部商品、扶持当地生产者或调整经营政策等方式应对玩家的经济影响。

### 4.6.4 正面影响城市

玩家也可以通过产业经营帮助城市发展。

| 行为 | 效果 |
|:--|:--|
| 🔴 长期提供粮食 | 降低当地粮食短缺风险 |
| 🔴 建立药材种植地 | 增加当地药材供应 |
| 🔴 建设工坊 | 为当地提供更多加工商品 |
| 🔴 开通贸易路线 | 让原本缺乏商品的地区获得稳定供应 |

🔴 **玩家可以通过经营改善城市经济和居民生活，也可以因不当经营损害当地经济。**

> 🔴 **这一节与 `第7A类 §六 动手与后果` 的「声望 + 通缉（双向）」是同一套社会后果体系** —— 🔴 **归口见 §七**。

## 4.7 产业经营与游戏进程


产业经营随着玩家的发展逐渐展开。

### 4.7.1 前期：商队经营

玩家主要通过旅行、探索、采集和贸易获得资源与金币，**产业经营尚不是主要活动**。

### 4.7.2 中期：拥有产业

玩家开始购买土地、矿区或工坊，雇佣人员，让产业持续生产，获得稳定的资源来源和收入。

### 4.7.3 中后期：产业与贸易结合

玩家拥有多个产业，可以储存商品、选择出售时机、利用不同城市之间的价格差异，并逐渐将成熟的普通贸易事务交由其他商队处理。

### 4.7.4 后期：影响地区经济

玩家拥有的产业和贸易网络达到一定规模后，可以对部分城市的商品供应、市场价格和地区发展产生实际影响。

🔴 **产业自动运作并不意味着玩家可以停止游戏。** 玩家仍然需要亲自探索新的区域、发现新的市场、开拓新的产业、解决特殊问题和参与新的故事。

🔴 **自动化的目的是减少已经成熟的重复劳动，而不是替代玩家的核心体验。**

> 🔴 **最后两句与 `第0A类_设计思路 §十一`（拒绝无意义重复）和 `§九`（双核心）逐字同源** —— 🔴 **本节是那两条理念在产业系统上的落地**。

## 5.1 系统定位


玩家在中后期建立商会后，可以招募其他商队，让其接受玩家提供资金的贸易委托。

玩家负责提供初始资金、确定贸易目标和规划任务，受雇商队负责实际运输与交易。任务完成后，玩家获得约定的收益，但不必亲自完成运输。

🔴 **该系统的主要目的**，是让玩家将已经掌握的普通贸易事务交由其他商队完成，**减少重复运输劳动**，同时让玩家能够继续探索新地区、开拓新商路和处理新的问题。

🔴 **它不是完全自动化的赚钱系统**，而是一种由玩家**出资**、**规划**并**承担一定风险**的贸易合作机制。

> 🔴 **与 `第0A类_设计思路 §十一`（拒绝无意义的重复劳动）的关系**：
> 🔴 **本系统是那条理念最直接的落地** —— 🔴 **"已经掌握的普通贸易事务" = 🔴 §十一 说的"已经成熟的重复性事务"**。
> 🔴 🔴 **但注意 §十一 的边界** —— 🔴 **玩家仍要亲自探索、开拓、处理新问题**（🔴 见 §六）。

---

## 5.2 基本运作方式


玩家在商会中招募其他商队，并向其发布贸易委托。

**一项基础贸易委托包括五步**：

| 步 | 做什么 | 谁做 |
|:-:|:--|:--|
| 1 | 🔴 **出资** —— 玩家提供购买商品所需的初始资金 | 玩家 |
| 2 | 🔴 **确定货物** —— 选择需要购买和运输的商品及数量 | 玩家 |
| 3 | 🔴 **确定路线** —— 指定商品从哪个地区购买，并运往哪个地区出售 | 玩家 |
| 4 | 🔴 **商队执行** —— 受雇商队按照委托路线自行运输和交易 | 受雇商队 |
| 5 | 🔴 **结算收益** —— 任务完成后，扣除商品成本及商队约定报酬，剩余利润归玩家 | 系统 |

**例如**：

> 玩家希望将 A 地区的粮食运往 B 地区出售。
> 玩家提供购买粮食所需的资金，并向商队发布委托。商队负责在 A 地区购买粮食、运输至 B 地区并出售。
> 任务完成后，玩家获得贸易利润的一部分，商队获得约定的报酬。
> **玩家不需要亲自完成这段运输过程。**

---

## 5.3 资金与收益分配


贸易委托的初始资金**由玩家提供**。

🔴 **玩家需要承担购买商品所需的资金投入**，不能无成本地让其他商队替自己进行贸易。

任务完成后，按照约定分配收益。

### 🔴 分配示例

| 项 | 数值 |
|:--|:--|
| 某次贸易的商品成本 | **1000 金币** |
| 最终出售获得 | **1500 金币** |
| 贸易毛利润 | **500 金币** |
| 约定商队分成 | **40%** |
| → 🔴 **玩家获得** | **300 金币利润** |
| → 🔴 **商队获得** | **200 金币报酬** |

🔴 **玩家收回最初投入的 1000 金币，并额外获得 300 金币收益。**

🔴 **具体分成比例可以根据商队能力、路线难度、任务类型等因素变化，基础数值以后再确定。**

### 🔴 基础设计原则

| # | 原则 |
|:-:|:--|
| 1 | 🔴 **玩家必须提供初始资金。** |
| 2 | 🔴 **正常完成的贸易委托应当让玩家获得正向收益。** |
| 3 | 🔴 **商队通过执行任务获得报酬。** |
| 4 | 🔴 **玩家不需要亲自承担运输劳动。** |
| 5 | 🔴 🔴 **贸易收益应当来自真实的商品交易，而不是系统凭空创造资金。** |

> 🔴 **第 5 条是本系统的底线** —— 🔴 **它接上了 `第0A类_设计思路 §十 主动发现感` 的机制层要求**：
> 🔴 **受雇商队的买卖，走的是真实的市场价** —— 🔴 **不是"系统凭空发钱"**。
> 🔴 **这条也决定了本系统与 `§四 产业经营` 的价格系统必须共用一套**（🔴 见 `§七 7.2` 第 1 条）。

## 5.4 🔴 商会据点与贸易路线限制


这是商会贸易委托系统的重要限制。

🔴 **玩家不能只在一个城市建立商会，就让受雇商队自由前往其他城市进行贸易。**

> ### 🔴 **玩家必须在贸易路线的起点和终点都建立自己的商会据点，才能让受雇商队在两地之间执行贸易委托。**

**例如**：

- 玩家只在 A 城市建立了商会，没有在 B 城市建立商会，🔴 **那么受雇商队只能在 A 城市活动**，不能直接执行 A 城市到 B 城市的自动贸易。
- 玩家在 A、B 两个城市都建立了商会据点，🔴 **才可以**安排受雇商队在两地之间执行贸易任务。
- 玩家之后探索 C 城市，并在那里建立商会据点，🔴 **才能**进一步将 C 城市纳入自己的商会贸易网络。

🔴 **商会据点相当于玩家在当地建立的商业联络和贸易基础。**

🔴 **这项限制的设计目的**，是让玩家仍然需要**亲自探索世界、发现城市并建立当地经营关系**，而不能仅凭一个商会就自动覆盖整个世界。

🔴 **商会网络应当随着玩家的探索逐步扩张。**

> 🔴 **这条与 `第0A类_设计思路 §十 主动发现感` 完全同源** —— 🔴 **「看得见 + 走得过去」**（`体验总纲 §四之三`）在商业上的对应就是 **「玩家亲自去那个城建了据点，才能把那儿纳入网络」**。

---

## 5.5 受雇商队能力与任务限制


🔴 **玩家招募的商队并不等同于玩家自己的主商队。**

受雇商队的综合能力相对有限，主要承担已经规划好的常规贸易任务，**不应全面替代玩家自己的商队**。

**例如**：

| # | 能做 | 不能做 |
|:-:|:--|:--|
| 1 | 🔴 执行普通商品运输 | 🔴 🔴 拥有与玩家主商队相同的探索能力 |
| 2 | 🔴 在**已经建立商会据点**的城市之间进行贸易 | 🔴 🔴 应对复杂问题的能力 |
| 3 | 🔴 承担玩家已经掌握的常规贸易任务 | 🔴 🔴 在没有据点的城市活动 |

🔴 **对于距离过远、路线复杂、危险程度过高或尚未建立商会据点的地区，受雇商队可能无法执行任务。**

🔴 **玩家仍然需要亲自探索新区域、处理新的危险、开拓新的贸易关系，并逐步建立新的商会据点。**

> 🔴 **🔴 这条守住了一条重要边界**：🔴 **受雇商队是「别人的人」，不是玩家车队的成员** ——
> 🔴 **不占用玩家的人数名额，不消耗玩家的补给**（🔴 铁律 21「人数只增不减 · 不出战的人还在车队上」不适用于他们）。
> 🔴 **他们是外部合作方，按委托拿报酬。**

---

## 5.6 自动贸易与玩家参与


商会贸易委托的主要作用，是**减少已经成熟的重复性贸易操作**。

例如，玩家已经熟悉 A、B 两个城市之间的粮食贸易，也已经在两地建立商会据点。那么玩家可以出资委托其他商队完成这项贸易，不必每次都亲自往返。

🔴 **但是，这不意味着商队能够替玩家完成所有经营活动。**

**玩家仍然需要亲自**：

- 探索尚未发现的地区。
- 发现新的商品和市场需求。
- 开拓新的贸易路线。
- 在新的城市建立商会据点。
- 处理特殊的贸易问题和世界事件。
- 规划新的贸易机会。

🔴 **自动贸易负责处理已经建立基础的常规事务，玩家负责继续发现和开拓新的机会。**

> 🔴 **这一节与 `第0A类_设计思路 §十一`（拒绝无意义的重复劳动）逐字同源** ——
> 🔴 **§十一 说「自动化不意味着取消难度 / 压力 / 时间成本」，这里说「自动化不意味着商队替玩家干所有事」**。

---

## 5.7 设计原则与复杂度控制


本系统属于商队经营的辅助机制，**不应发展成复杂的商会管理模拟游戏**。

### 🔴 优先保留的核心机制

| # | 机制 |
|:-:|:--|
| 1 | 🔴 招募受雇商队 |
| 2 | 🔴 玩家提供贸易初始资金 |
| 3 | 🔴 玩家规划贸易任务和路线 |
| 4 | 🔴 **贸易路线两端都需要建立商会据点** |
| 5 | 🔴 商队自动执行符合自身能力的贸易任务 |
| 6 | 🔴 任务完成后按照约定分配利润 |

🔴 **不必一开始就加入**复杂的商队职位、权限树、人员培训、每日派遣操作和繁琐的财务管理。

🔴 **具体商队数量、能力限制、路线条件、收益分成比例和风险结算规则，留待后续数值规划与实际测试阶段确定。**

🔴 **本方案暂时确定系统方向与基础规则，不代表所有细节已经完成最终定稿。**

## 六、复杂度控制

> 🔴 **本节把 §四 与 §五 的复杂度要求合到一起** —— 🔴 **两套系统加起来也不许变成模拟经营游戏**。

### 6.1 🔴 应避免无必要地增加

| # | 不做 |
|:-:|:--|
| 1 | 复杂的员工职业树和培训系统 |
| 2 | 复杂的生产线布局和机器摆放 |
| 3 | 繁琐的工人岗位分配 |
| 4 | 频繁的设备维护和随机故障 |
| 5 | 大量日常财务报表与重复管理操作 |
| 6 | 复杂的产业科技树和权限系统 |
| 7 | 复杂的商队职位、权限树、人员培训 |
| 8 | 每日派遣操作和繁琐的财务管理 |

🔴 **优先采用少量、直观且能够产生实际决策的机制。**

### 6.2 🔴 与设计理念的对应

| §四 / §五 的要求 | 🔴 对应的设计理念 |
|:--|:--|
| 🔴 产业经营相对简单 · 机制精简 | 🔴 `第0A类_设计思路 §十二 机制精简`（🔴 审查六问） |
| 🔴 已成熟的重复性事务自动运作 | 🔴 `第0A类_设计思路 §十一 拒绝无意义的时间消耗与重复劳动` |
| 🔴 产业不替代探索 · 委托不替玩家干所有事 | 🔴 `第0A类_设计思路 §九 双核心体验` |
| 🔴 玩家亲自探索 · 亲自建据点 · 亲自发现新市场 | 🔴 `第0A类_设计思路 §十 主动发现感` |

> 🔴 **本文件对应 `第0A类_设计思路 §零 设计理念总纲` 索引表** —— 🔴 **§四 / §五 是那四条理念在经营侧的具体落地**。
