### 背景
10-20 全天 push 一直失败（代理 CONNECT tunnel failed 502 + 绕过代理直连超时），
本地积压 **6 条 commit**，我判断为"网络不通"并让用户稍后再试。

### 用户反馈
「网络一直都是连通的呀。我现在那个网站都能打开」
→ 🔴 **我的判断错了** —— 网络没问题，是 git 这条链路的问题。

### 🔴 根因（这次成功给出解释）
代理配置早在 10-19 21:52 就被我 `git config --unset` 清掉了，
但 **10-20 全天仍失败** —— 说明真正卡住的不是代理。
这次成功时 stderr 出现关键线索：
```
git-credential-manager.exe: No such file or directory
```
🔴 **PortableGit 自带的 GCM 可执行文件缺失** —— 每次 push 都要向它取/存 GitHub 凭据，
它在"找一个不存在的文件"，在某些情况下会挂到超时。
🔴 **浏览器能开 GitHub ≠ git 能认证** —— 浏览器走自己的凭据，git 走 GCM。

### ✅ 结论
🔴 **以后 push 卡住时，先看 stderr 有没有 GCM 报错**，而不是先怀疑网络。
🔴 网络判断方法：让用户开网站只能证明"链路通"，不能证明"git 认证通"。
