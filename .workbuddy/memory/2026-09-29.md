## 箱子（扩容箱 / 外挂箱 / 储存容器）设定评估 —— 纯只读，未落库

**背景**：承接 `09-28` 的「车队改造」话题。用户上轮否掉了 AI「该删扩容箱/外挂箱」的判断（**"没有生态位就给它开一个"** —— 空 = 待补 ≠ 该删），提出用箱子做**平缓成长曲线**（车买来格数不高，靠箱子加）。

### 🔴 AI 两次判断都被用户纠正（记下来防再犯）

**第 1 次**：AI 判「扩容箱/外挂箱该删」→ 被纠正：**"没有生态位就给它开一个…不要因为它什么都没有就删"**。
→ **判据错了**：该问"它有没有独占的场合或代价空间"，**"空" = 待补 ≠ 该删**。

**第 2 次**：AI 判「q 降到 700、箱子补到 900 不成立（要 10~20 个箱子/车，荒谬）」→ **也错了**。
- AI 的错因：**按"扩容箱"（自占格、净收益低）算的**；用户的主体是**外挂箱**（不占内部格），10 个 × 20 格 = 净 +200 格。
- 用户澄清：「降到 700」**只是比喻，具体数值他没写** —— AI 把比喻当提案反驳，**打的是空气**。
- 用户同时给出**挂点数上限**（这正是 AI 说"缺的闸"）：**小型 6 / 中型 10 / 大型更多**。
- → **结论：用户方案在数学上成立** —— q 可降、箱子补回来，曲线更平缓。

### 🔴 但有一条硬冲突 + 一条新风险（待用户定）

**硬冲突**：用户说的是「**小型车 / 中型车 / 大型车**」—— 而这套**车型分级已经废了**（`6A §11.1 L478` 明文：「旧『小型车 64 格 / 中型车 128 格 / 大型车 192 格』三档车型分级**已废**」，现行只有「货车 / 单车」）。
→ **挂点数不能挂在"车型"上**，应挂在 **`q`** 上（`04 §0.1 A15`：换车 = 更大的车 = 更多挂点），这样也不破坏 A15 那条「公式里只许出现 `q`」。

**新风险：三重相乘**。外挂格 = **车数 × 挂点数/车 × 单箱格** —— 比「车数 × q」**还多一个因子**，而 `04 §15.2` 已定「**车数与格数不许同时涨**」（且该铁律目前**处于被顶穿状态**）。
→ 必须锁死一个因子。建议：**单箱格数恒定** · 挂点数随 `q` 走 · 车数有上限（`§0.7.4` 12~15）。

**连带**：`§0.7.8` 可达 = 货舱 ÷ 常数 → **箱子加格会让可达线性上浮**，会顶 `04 §15.2 L1888` 的「后 220~260 天」护栏。→ **「q + 满配箱子」必须设计成刚好够到目标天数，不能两头顶。**

### 查出的 8 个问题

**🔴 必补（不补 = 纯加成 / 空话）**
1. **数量上限完全缺失** —— `§11.1` / `§11.4` 都没写"每车能装几个" → 钱够就能无限加格 → **q 升级当场贬值**（玩家算得出"装箱子比换车便宜"）
2. **`§11.1 L498`「外挂箱 = 增加负重上限」是句废话** —— `§11.2 L516`：**负重上限 = 货舱格数 × 2**（格是自变量，负重是因变量）→ 格一加，负重自动涨。**用户上轮设想的"格子够但负重不够"在现行公式下永远不可能发生**
3. **"保温箱"没有对立面** —— 文件里**没有"货物会变质"的机制**（`5A` 只有"货物受潮"暴雨、"保鲜收益"天气）→ 保温箱不是"补一截"，是**新开一个机制**

**⚠️ 连带（不补会打架）**
4. **箱子的格会进可达公式**（`§0.7.8`：`单程可达 = 货舱 ÷ (2 × 每日补给占格)`）→ 箱子**偷偷加射程**
5. **三条代价全要新接口**：被抢（`5A §3.14` E12 现在只有过路费 P1 0.45）· 优先损坏（`04 §0.7.4` 车损按车计、箱子无耐久）· 只能放便宜货（需"外挂箱专属货位"数据结构）

**🧹 文档自身问题**
6. **`§11.1 L478` 自相矛盾** —— 「**现行扩容方式 = 加挂货车**」与同页「扩容箱」打架
7. **`§11.1` 四件"配件"里，装甲板 / 加固车架其实有槽**（`§11.3` 装甲槽 / 车体结构槽）→ 与八槽体系重复的口径
8. **单车不能挂箱**（单车"不载货、不计耐久"）—— 需写明，否则玩家会想给载人车加箱

### 建议结构（⚠️ AI 提案，未落库）

| 件 | 装哪 | 加格 | 上限 | 代价 |
|:--|:--|:--|:--|:--|
| **扩容箱** | 车内 | 小（自占格 → 净收益低） | **每车 ×1** | 改装费 + 吃格 |
| **外挂箱** | 车外 | 中（不占内格） | **每车 ×1** | 被抢 / 会坏 / 只能放便宜货 |
| **功能箱**（防潮 / 封存 / 药品 / 材料 /[保温]） | 车内 | 0 | 看现有格 | **占格换功能** |

**定位一句话**：**扩容箱 = 补零头（"差 30 格就够了，不必换车"）· 外挂箱 = 搏一把 · 功能箱 = 换功能**。

## ✅ 灰度刻度再改「1000 制」落库（用户当场反驳 AI「不该放大刻度」的判断）

### 🔴 AI 判错了一次 —— 把「压迫感」和「惩罚」混为一谈

### 🔴 用户本轮追加的核心要求：**内部事件频率必须压低**

原话：「**内部事件触发概率要降低一点，绝对不能可能每天都触发，甚至不要每五天就触发一次，因为内部事件惩罚很重**」「**人越多触发概率越高**」「**或者说士气低才会触发，或者说特定的（走得太累 / 饿）才会触发，不然惩罚太严重**」。

→ 落成 **三重闸门**：
```
闸门 1 · 压力源   无压力 → P = 0，直接跳过
闸门 2 · 总冷却   距上次内部事件 < N 天 → P = 0，跳过
闸门 3 · 抽签     P = 基准频率 × 人数系数 × 压力强度，且 ≤ 每日上限
```

🔴 **这条改动推翻了 `04 §0.7.7 ①` 的旧频率表** —— 旧表写「50~70 人**每天 1 次** / 70+ 人**每天 2~3 次**」，**与"惩罚重 → 频率必须低"直接冲突**。新口径：**频率随人数上升，但被总冷却封住上限，永不到"每天一次"**。

### 🔴 本轮定下的设计原则（值得复用）

1. **人数必须做「乘数」，不能做「加项」** —— 加项会让「人少+压力重」与「人多+压力轻」**同概率**（违反直觉）；乘数才有「14 人扛得住、50 人扛不住」。
2. **降频必须有「与压力无关的独立闸」** —— 用**总冷却**（而非"概率算小一点"）承担频率上限。**否则压力一大就把降频绕过**，降频变空话。
3. **"惩罚重"与"频率低"是配套的** —— 惩罚越重的东西，越要靠**间隔**而非**概率**去限频（概率有长尾，间隔没有）。
4. **"太累 / 饿"是独立扳机，不是"士气低"的子项** —— 它们是**身体信号**，出现得比情绪更早。用户点名要把它们并列。
5. **有概率公式却没类型表的系统 = 漏写** —— 旧内部事件公式有 9 个修正项，却**没有 I 类表**：**概率有"源"，玩家看到的必须是"形态"**。新做法：**一个压力源配一类**。
6. **分类维度要从"内容"换成"玩家动作"** —— 按内容分（E1 遇敌 / E2 道路）必然**维度不纯**（E2 与 E10 撞、E9 与 E13 撞）；按**动作**分（打 / 修 / 采 / 换 / 问）才能**互不重叠、也不漏**。

- 🔴 **用户原话**：「我们这个游戏**基本上 50% 都是要靠随机事件撑着的**。**随机事件太少，玩家就会很无聊**。所以**随机事件最好多一点，而且要有新意一点**。」
