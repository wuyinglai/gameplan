## 二 · 🔴🔴 本机 git 推不上去 —— 代理全挂（🔴 记录下来，别再重复踩）

### 现象
```
fatal: unable to access 'https://github.com/wuyinglai/gameplan.git/':
  schannel: failed to receive handshake, SSL/TLS connection failed
```

### 🔴 本机代理端口全查了
| 端口 | 进程 | 结果 |
|:--|:--|:--|
| **7897** | verge-mihomo（Clash Verge） | 🔴 **TLS 握手失败** |
| **7892** | verge-mihomo（Clash Verge） | 🔴 **连接被重置** |
| **59000** | WorkBuddy（PID 17928） | 🔴 **502**（上游代理挂了） |
| 直连 | — | 🔴 **21 秒超时连不上** |

🔴 **git 的 http.proxy 配的是 7897**，🔴 环境变量 `http_proxy` 是 59000 —— 🔴 **两个不一致**

### 🔴 试过但不管用的
- `http.sslBackend=openssl` → 仍是 `unexpected eof while reading`
- `http.sslVerify=false` → 无效
- `http.version=HTTP/1.1` → 无效
- `curl -x 各端口 https://api.github.com` → 全 000

### 🔴 唯一通的路：SSH 22 端口
```
SSH-2.0-9bd49d50        ← github.com:22 能连上！
git@github.com: Permission denied (publickey).   ← 🔴 但本机没有 SSH 密钥
```
🔴 **没有 `~/.ssh/` 目录** —— 🔴 要用 SSH 推，得先生成密钥并加到 GitHub 账号

### 🔴 结论
🔴 **不是 git 配置问题，是代理节点侧断了** —— 🔴 Clash Verge 里换个节点或重启服务就能恢复
🔴 **WebFetch 能通 GitHub** —— 🔴 因为它走 WorkBuddy 服务端出口，不经本机代理
🔴 **所以「查远端状态」用 WebFetch，「推上去」必须本机代理通**
