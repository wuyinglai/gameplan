## 本批：「不领工资 / 不消耗补给」的世界观解释定案（`第3A类 v4.0` · `第6A类 v4.7`）

**机制一个字未改**，只补解释。

## 问题是怎么暴露的

用户连问五轮，每一轮都在指同一个地方：**战斗人员跟商队走，为什么不消耗钱和粮食？逻辑说不通。**

我先后提了五个方案，**全部被当场否掉**：

| 我的方案 | 用户否掉的理由 |
|:--|:--|
| 分成制（核心 vs 雇佣） | **双重标准** —— "那非核心成员不还是要领工资吗" |
| 大本营往返制 | **"跑 100 天回大本营，玩家会觉得白跑"** |
| 按人头收消耗 | **"三头堵"** —— 不带就消耗少、带全了就消耗多，怎么都不对 |
| 搭车客 | 🔴 **"你偏离初衷了 —— 你把商队成员直接消除了"** |
| 合伙人制 | **"世界观没到那程度，城市有工资系统"** |

**我的问题：在打补丁，没有先确认"这个解释要服务于哪条机制"。**

## ✅ 最终答案（用户直接给出）

> **「他们跟着你，是因为他们知道你还会雇佣他们。」**

- **他们不是签了约的雇员**，而是**跟着队伍等机会的人** —— 今天的活干完，下一段路你还可能用他们。
- **这是他们的生路**：🔴 **商队本来就稀少** —— 引 `第7A类` 原文（九城之间只剩零星几条路、"条数少、人不多、不繁荣"）→ 满世界能让他们赚钱的路子**没几条**，**跟着商队是最赚钱、最稳当的一条**。
- **为什么不发工资、不消耗补给**：🔴 **因为玩家还没有雇佣他们**。**雇佣 = 建立关系 = 领工资 + 吃商队的粮**；没被雇佣 = 只是跟着走 → **口粮自己买、工钱不领**。**不是克扣，是"还没到那一步"。**

**三条疑问由此全成立**：
- 为什么不领工资 → **没被雇佣**
- 为什么不消耗 → **口粮自己买**
- 为什么跟着你 → **等你雇佣他**（商队稀少，这是他最赚钱的生路）

## 教训（重要，别再犯）

1. 🔴 **解释一个机制前，先确认"这个解释要服务于哪条既定机制"** —— 我连续五个方案都在试图**改机制或绕过机制**，而不是**给既定机制找解释**。
2. 🔴 **用户说"偏离初衷"就是在说：你把我设计的东西改掉了，不是没解释清楚。** 遇到这种情况应该**回到最初的机制**再想，而不是继续优化偏离后的方案。
3. **连续否掉 3 次以上就该停下来问** —— 我被否了五次才等到正确答案，中间浪费大量。**更好的做法是第三次就问"我理解的对不对，你要的到底是机制还是解释"**。

## 本批（二）：牲畜系统裁定「只作背景，不做系统」（`第3A类 v4.1` · `第2A类 v2.4` · `23`）

用户问「**要不要有这个系统，它现在就仅仅只是一个空壳，没有做任何对齐和接口，如果要做会很麻烦**」。

**判断：不做系统，但保留在设定里。**

- **原空壳表全部作废**：每天饲料 1 份/头占车厢格 / 不消耗水 / 种类载重·耐旱·稳定性差异 / 城市购买 —— **全都没有机制接口**。
- **明确不做**：无饲料 / 无水源 / 无耐力 / 无买卖 / 无疾病死亡；**不进硬账**（商队口粮不按牲畜算）、**不算车数与编制**。
- **保留的唯一意义 = 画面**：「后末日的世界里，商队是用牲畜拉车的」（粮野城产马匹与驮畜、黑石城缺驮畜 · `第7A类` 区域表）。
- 🔴 **真正让它不能做的原因**：**它唯一的功能是"让车走得快"，而这件事 `23 §2.2` 已用「动力抬 `S`」解决** —— 一旦牲畜能加 `S`，就是**凭空多出一条提速轴**，直接违反 2026-10-05「**速度恒定、每格恒 20 点**」裁定。真做起来要接**饲料/水源/耐力/车速/地形/疾病/价格** 七八个接口，**麻烦且收益不抵**。
- 🔴 **连带**：`23 §2.2` 动力轴「**驼兽**」→ **改称「动力装置」**（驼兽本质是牲畜，留着这词会让人以为**牲畜能抬 `S`**）；`23 §5.4`「引擎与驼兽」→「动力装置」；配套代价里「驼兽沿途自采、不耗粮」**已删**。
- **术语统一**：「**牲畜**」是类目（马/驴/驼），「**驮畜**」只是其中一类；旧写法"**默认统一按驮畜处理**"**作废**（把子类当全集）。
- **落库**：`0A 第3A类 §4.5.4` 整节改写 + **v4.1** · `0A 第2A类 §2` + **v2.4** · `23 §2.2 / §5.4` · `01_废弃旧口径清单`（新增 5 条）· `00_总纲与撰写顺序`（第 39 批）。

## 🔴 重大方向讨论（未落库 · 2026-10-09 下午）：体验核心 = **旅行**

用户说「**我真正想要带给玩家的是一种旅行的体验**」—— 这是**这几天第一句"总纲级"的话**，此前所有机制讨论都没有它。

### 已确认的方向

| 项 | 内容 |
|:--|:--|
| **核心动词** | 从「**算**」（算成本、算行程）→🔴「**走**」（走一段路，看路上发生什么） |
| **订单的作用** | 🔴 **只规定起点和终点**，**路上怎么走玩家自己决定**；**期限 ≥ 最短路程 × 2**（让绕路永远安全） |
| **重心转移** | 🔴 **从资源管理偏到叙事** |
| **路上的四种内容**（用户说"四种可以都有"） | **A 看变化**（灰度/天气/地形）· **B 碰到人**（商队/路人）· **C 碰到事**（传闻/新地方/传说/事件）· **D 安静地走**（日子一天天过） |
| **遭遇频率** | 🔴 **二三十天一次**（"没必要一直碰到人"） |
| **传闻的特色** | 🔴 **传说可能是有依据的** —— 玩家**可以根据这些依据获得东西**（= 信息不是死的知识，而是**可验证的线索**） |

### 🔴 AI 观察（重要，尚未与用户讨论完）

1. **这个转向能解掉今天所有烦** —— 消耗/离队/工资/牲畜**全是"资源管理"的问题**；**"资源管理"追求最优解，"叙事"只要求"合理"**。今天烦了五天，是因为**在给一个叙事游戏做数值优化**。
2. **⚠️ 现有一个缺口**：`第5A类` 事件库里"听说点什么"这类**是空的** —— E9 痕迹情报 / E13 地标视野都要求**玩家亲自去看**，**没有"别人告诉你"的通路**。→ 建议**新开一类事件（E14 传闻？）**，低频触发。
3. **⚠️ 三个风险（已向用户提出，待回应）**：① **重复感**（短文本量大，但反复看到同一批传闻 = 沉浸崩塌，是程序化叙事的头号杀手）· ② **节奏失控**（玩家永远想rush，除非机制上不允许）· ③ **卡牌战斗投入可能浪费**（若战斗变少，那套系统就白做了）。
4. **🔴 待解决的核心张力**：**"允许慢"不等于"值得慢"** —— 玩家为什么宁可多花补给也要绕路？**必须有一个机械层面的理由**（稀缺），否则叙事会被跳过，游戏变成没人玩的"走路模拟器"。
