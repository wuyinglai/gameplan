# 《余烬商队》开发流程 · 单元 01

> 📌 **这份文件怎么用**：🔴 **一条一条复制下面的「指令」发给写代码的 AI**，它做完一条、把结果给你，你确认后再发下一条。
> 🔴 **到「测试节点」时停下** —— 那是你亲自跑一遍、看结果对不对的时候。
> 📖 **规则依据**：`../基础文档/第1B类_旅行基础.md` · **验收依据**：`../开发用例/第1B类_测试用例.md`

---

## 一、总划分：5 个大阶段

> 🔴 **划分原则**：**每个大阶段结束时，程序必须能跑出一点看得见的东西** —— 不能出现"写了 500 行但看不到任何变化"。

| 大阶段 | 干什么 | 做完能看见什么 | 🔴 你要测吗 |
|:-:|:--|:--|:-:|
| **0** | 搭架子 | 程序能启动，打印一句话 | 🔴 **不用** |
| **1** | 数据 | 🔴 **地图能画出来** | ✅ **测一次** |
| **2** | 单点逻辑 | 时间 / 体力 / 天气 / 侦察各自能单独算 | 🔴 **不用** |
| **3** | 串起来 | 🔴 **能走一格、能跨日** | ✅ **测一次** ← **最关键** |
| **4** | 跑通全程 | 🔴 **能从起点走到终点** | ✅ **测一次** |

```
阶段0 搭架子 ──→ 阶段1 数据 ──→ 阶段2 单点逻辑 ──→ 阶段3 串起来 ──→ 阶段4 跑通
                     ▲                              ▲
                 你测这里                      你测这里（最重要）
```

> 🔴 **阶段 2 不测是有意的** —— 那四个模块单独算对了就行，**等串起来才有意义**。串不起来再回头查。

## 二、指令清单（按顺序发，一条一条来）

### 阶段 0 · 搭架子

#### 指令 0-1：定技术栈并把项目跑起来

```
【任务】用【技术栈：待填】创建一个空项目，让它能运行并输出一句话。

【照哪份文档】B类_开发文档/基础文档/第1B类_旅行基础.md §3.6（模块划分）

【要做的事】
1. 按 §3.6 的表格建好 7 个文件（地图/时间/体力/天气/侦察/结算/主循环），
   先只留文件名和一句"待实现"的注释
2. 写一个入口，能运行并打印"程序启动成功"

【完成标准】
- 运行后屏幕上出现「程序启动成功」

【做完后】
把①目录结构截图或列出 ②运行结果 贴给我。
我确认后再给你下一条指令。
```

> 🔴 **发这条之前先告诉我技术栈**（引擎 + 语言）。后续所有指令都按这个来。

### 阶段 1 · 数据

#### 指令 1-1：写地图模块

```
【任务】写「地图」模块：能生成测试地图、能按坐标查某一格。

【照哪份文档】第1B类_旅行基础.md §3.5.1（格子结构）§3.5.2（格子类型）§3.6（地图.py）

【数据结构（照抄，不许自创字段）】
格子 = {
    "坐标": (x, y),
    "类型": "野地",
    "路况档": "普通",
    "地点名": None,
    "已探明": False,
}

【要做的事】
1. 能创建一张 30×30 的地图
2. 能按坐标查询某一格
3. 地图数据放在独立的配置文件里，不要写死在代码里

【完成标准】
- 调用"创建地图"后，能把地图打印/画出来

【做完后】
把地图打印出来给我看。我要能看到：两个地点、一片林地、一片山、水、路。
```

#### 指令 1-2：铺测试地图

```
【任务】在刚才的地图上摆出测试用的内容。

【照哪份文档】第1B类_旅行基础.md §2（测试地图要求）

【必须包含】
- 起点：一个城市（地点名="起点城"）
- 终点：一个城市（地点名="终点城"）
- 🔴 两条路：
  · 路A —— 格数少，但路况是"差"和"恶劣"
  · 路B —— 格数多，但路况是"普通"和"好"
- 铺满 §3.5.2 里的各种格子类型

【完成标准】
- 把地图打印出来，能一眼看出两条路长度不同

【做完后】
贴地图给我看。我要确认：两条路真的不一样长。
```

> 🔴 **你在这里测一次** —— 打开看一眼，两条路在不在，长得明不明显。

### 阶段 2 · 单点逻辑

#### 指令 2-1：写时间模块

```
【任务】写「时间」模块：推进小时、判断跨日。

【照哪份文档】第1B类_旅行基础.md §3.6（时间.py）§3.5.4（顺序）

【规则】
- 一天 = 07:00 到 19:00
- 走 1 格 = 2 小时
- 小时到 19 就必须跨日（不许卡在 19）
- 🔴 这个模块不管"跨日要做什么"，只管"现在是第几天第几小时"

【完成标准】
- 连续调用"推进2小时"20次：应该跨日一次，回到第2天07:00

【做完后】
把这20次调用后的天数、小时打印给我看。
```

#### 指令 2-2：写体力模块

```
【任务】写「体力」模块：够不够、扣、每日回复。

【照哪份文档】第1B类_旅行基础.md §3.6（体力.py）§3.5.3（状态）

【规则】
- 体力上限 100，每天回复 50（不许超过 100）
- 走 1 格扣 15（天气/路况加成本轮先按 0）
- 🔴 体力不够时必须拒绝，且拒绝时不消耗任何东西

【完成标准】
- 体力 100 时走一格 → 剩 85
- 体力只剩 10 时走一格 → 被拒绝，且还是 10

【做完后】
把这两种情况的输出贴给我。
```

#### 指令 2-3：写天气模块

```
【任务】写「天气」模块：掷天气、算每格消耗加成。

【照哪份文档】第1B类_旅行基础.md §3.6（天气.py）
数值照抄 第5A类_天气与事件系统_权威口径.md §2.3

【规则】
- 天气段有持续天数，到期重掷
- 恶劣天气每格 +5，灰烬风暴 +10，其他 +0
- 🔴 掷骰必须能指定结果（测试要用），平时随机

【完成标准】
- 指定"暴雨"时，加成是 5
- 指定"灰烬风暴"时，加成是 10

【做完后】
把指定三种天气时的加成打印给我。
```

#### 指令 2-4：写侦察模块

```
【任务】写「侦察」模块：提升信息等级、标记已探明。

【照哪份文档】第1B类_旅行基础.md §3.6（侦察.py）
规则照抄 第1A类 §9.0~9.6

【规则】
- 侦察花体力换信息等级
- 🔴 侦察只能提升信息等级，绝不能返回坐标
- 玩家实际走到某地点 → 该地点标记为已探明

【完成标准】
- 侦察一次：信息等级上升
- 走进一个没去过的地方：那格"已探明"变成 True
- 🔴 侦察函数里不得出现任何"返回坐标"的逻辑

【做完后】
贴侦察前后的信息等级、还有那格的"已探明"变化。
```

### 阶段 3 · 串起来 🔴 最关键

#### 指令 3-1：写结算模块（跨日）

```
【任务】写「结算」模块：跨日那一刻发生什么。

【照哪份文档】第1B类_旅行基础.md §3.6（结算.py）§3.8（流程图）

【跨日必须做三件事，顺序固定】
1. 体力 +50（不许超过 100）
2. 天气剩余天数 -1，到期就重掷
3. 天数 +1，小时回到 07:00

【🔴 铁律】
- 跨日只能在一个地方触发（不许主循环和结算各做一次）
- 不许出现金币、食物、士气这些—— 那些是后面单元的事

【完成标准】
- 体力 10 跨日 → 变成 60
- 体力 100 跨日 → 还是 100（不许变成 150）

【做完后】
贴这两种情况的输出。
```

#### 指令 3-2：写主循环（串起来）

```
【任务】写「主循环」：把前面所有模块接起来，让玩家能真的走一格。

【照哪份文档】第1B类_旅行基础.md §3.8（主循环流程图）—— 🔴 严格按那个顺序

【"走一格"的固定顺序，不许调换】
1. 查体力够不够 → 不够就拒绝，且什么都不扣
2. 体力 -15（加上天气/路况加成）
3. 时间 +2 小时
4. 换到相邻格
5. 当前小时到 19 了吗？→ 到了就调用「结算」
6. 如果走到的是新地点，标记已探明
7. 回到第1步等下一个指令

【完成标准】
- 从起点连续走 3 格：体力 100 → 55
- 再走到 19:00 触发跨日 → 第二天 07:00，体力 55+50=100

【做完后】
把连续走3格 + 跨日之后的完整状态（天数/小时/体力/坐标）贴给我。
```

> 🔴 **你在这里测一次（最重要）** —— 这是第一次能真正"走"起来。跑一下，用测试用例的 TC-01-001 和 TC-01-002 对一遍。

### 阶段 4 · 跑通全程

#### 指令 4-1：两条路对比

```
【任务】把路况加成接进体力消耗，让两条路真的产生不同代价。

【照哪份文档】第1B类_旅行基础.md §5（移动消耗）

【要做】
- 路况影响每格消耗（具体档差暂时用：好+0 普通+0 差+5 恶劣+10）
- 🔴 每格消耗只会变高，永远不会变低

【完成标准】
- 从起点走"路A"（近但路况差）和"路B"（远但路况好）
- 输出两条路的：总天数、总体力消耗
- 🔴 两个数字必须不一样！

【做完后】
把两条路的对比表贴给我。我要确认数字不一样。
```

#### 指令 4-2：抵达终点

```
【任务】走到终点时，给出"已抵达"的提示并停下。

【照哪份文档】第1B类_旅行基础.md §4 步骤6

【要做】
- 走进终点格 → 提示"已抵达终点城"
- 🔴 本轮到此为止，不要做进城买东西（那是单元02的事）

【完成标准】
- 从起点一路走到终点，能正常抵达并提示

【做完后】
贴从出发到抵达的完整记录（每天的天数/小时/体力/坐标）。
```

> 🔴 **你在这里测一次** —— 完整跑一趟，看是不是真的能走到。

## 三、🔴 三个测试节点（你亲自跑的时候）

| 节点 | 在哪 | 测什么 | 对应用例 |
|:--|:--|:--|:--|
| ✅ **第一次测** | 阶段 1 之后 | 地图画出来了吗？两条路在不在？ | 眼看一下 |
| 🔴 **最关键那次** | **阶段 3 之后** | **能走一格吗？跨日对吗？** | **TC-01-001 ~ 006** |
| ✅ **最后一次测** | 阶段 4 之后 | 能从起点走到终点吗？ | TC-01-011、012 |

**测的时候要做的只有一件事**：🔴 **让 AI 把"预期结果"和"实际结果"列成一张表**，你逐条看两列一不一样。

## 四、🔴 发指令时要注意的三件事

| # | 注意 |
|:-:|:--|
| 1 | 🔴 **一条一条发**，别一次把整个阶段的指令全发过去 —— 中间要确认 |
| 2 | 🔴 **AI 说"完成了"不等于做对了** —— 要它**把结果打印出来**，用数字说话 |
| 3 | 🔴 **规则不清就让 AI 停下来问**，不许它在代码里自己猜 |
