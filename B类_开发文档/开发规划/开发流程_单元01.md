## 2. 切片清单（5 刀，每刀做完都有能跑的东西）

```
① 骨架      → vitest 能跑
② 🔴 一条完整细路  → 能走一格 + 会跨日      ← 你验收①
③ 加天气     → 天气能改变每格消耗
④ 加路况     → 两条路代价不同            ← 你验收②
⑤ 边界与耐久 → 长时间跑不出错            ← 你验收③
```

| 刀 | 做完能跑出什么 | 覆盖用例 |
|:-:|:--|:--|
| ① 骨架 | `npx vitest run` 通过 1 条 | — |
| ② 一条完整细路 | **从起点走一格 → 体力/时间对 → 19:00 自动跨日** | **TC-001~005** |
| ③ 加天气 | 暴雨时每格消耗从 15 变 20 | TC-006、TC-008 |
| ④ 加路况 | 走两条路，消耗/天数**不一样** | TC-007、TC-011 |
| ⑤ 边界 | 18:00 走一格被拒 / 连跑 10 天不出错 | TC-012~015 |

> 🔴 **为什么第 ② 刀这么早就要跑通全链路** —— 因为"走一格"必须同时用到 **地图 · 时间 · 体力 · 结算 · 主循环** 五个模块。**早串早暴露接口问题**，比四个模块各写完再串便宜得多。

### 指令 ② · 🔴 一条完整细路（核心）

```
【任务】让玩家能从起点走一格，且 19:00 自动跨日。这是本单元的核心，不许跳过。

【依据】B类_开发文档/基础文档/第1B类_旅行基础.md
       §3.5.4 三条规则 · §3.6 模块划分 · §3.8 主循环（严格照那个顺序）

【🔴 允许改动】只允许 E:\WYY\src\b01\ 下的文件。其他一律不许动。

【模块与职责（互不重叠）】
  地图.ts  —— 存格子、按坐标查询            ← 不管时间体力
  时间.ts  —— 推进小时、判断到 19:00      ← 🔴 不管跨日做什么，只报"该跨日了"
  体力.ts  —— 够不够 / 扣 / 每日回复        ← 不管谁触发
  结算.ts  —— 🔴 跨日那一刻做的事（只此一处）
  主循环.ts —— 🔴 唯一把上面串起来的地方

【主循环九步，一步不许调换】
 1 目标坐标在范围内吗      否→拒绝，什么都不扣
 2 目标格相邻吗            否→拒绝
 3 目标格可通行吗          否→拒绝
 4 体力够吗（15+天气+路况）否→拒绝
 5 🔴 剩余时间够跑完这一整格吗 否→拒绝（不许做一半）
 6 全过→执行：扣体力→时间+2h→换格
 7 小时到 19 了吗          是→立刻调结算（不用玩家再点）
 8 走到没到访过的地点→标记已到访
 9 回到第1步

【本刀不做】天气加成、路况加成（下一刀）、主动侦察（属单元04）

【完成后应出现】
- 🔴 **场景 A（半天收工）**：走 3 格 → 体力 100→55 → 主动「结束当天」→ 🔴 55+50=105 **被上限封顶为 100** → 第 2 天 07:00 体力 **100**
- 🔴 **场景 B（走满一天）**：一路走到第 6 格（19:00）→ 🔴 立即跨日 → 跨日前体力 100−15×6=**10** → 10+50=**60** → 第 2 天 07:00 体力 **60**
  🔴 **不许把场景 A 的 100 写成场景 B 的结果** —— 这是本单元最容易写错的数字
- 「结束当天」：**不改坐标 · 不扣移动体力 · 不额外推进 2 小时** —— 只调一次跨日
- 🔴 **幂等**：19:00 已自动跨日后再调「结束当天」→ **不能再跨一次**（按钮不可用或幂等保护）
- 体力 10 时走一格 → 拒绝，体力/时间/坐标全不变
- 18:00 走一格 → 拒绝（要 2 小时但只剩 1 小时），🔴 什么都不扣
- 🔴 **独立时间测试**：只调「推进 2 小时」20 次 → **第 4 天 11:00（跨日 3 次）**；调 6 次 → 第 2 天 07:00

【AI 自检】至少写这些断言：TC-001（走一格）· TC-002（跨日）·
           TC-003（体力封顶：80+50=100 · 30+50=80）· TC-004（体力不足拒绝）·
           🔴 **新增：场景 A 与场景 B 分别断言** · 🔴 **新增：15:00 且体力 0 时结束当天** ·
           🔴 **新增：同一次日界内跨日只发生一次**（日期+1 一次 · 时钟一次 · 体力一次 · 天气一次）
【进下一步的条件】上面所有"完成后应出现"全部断言通过，且 `git diff --name-only` 只列出本指令许可的文件。
【失败怎么办】🔴 跨日被触发两次 → 检查是不是主循环和结算都写了体力回复，修成只有 `结算.跨日()` 一处。
           🔴 规则有疑问 → 停下报告，不要自己选一个方案。
```

```
【任务】把路况接进每格消耗，让两条路产生不同代价。

【依据】第1B类_旅行基础.md §2.1（两条路规格）· §3.5.2（格子路况档）

  ③ 有山和水（不可通行）。具体规格见施工图 §2.1

【🔴 允许改动】只改 src/b01/ 下的文件。地图是内容不是逻辑，不许写死在代码里。

  好 +0 · 普通 +0 · 差 +5 · 恶劣 +10
  🔴 这组值是项目主为测试临时定的，不是正式平衡数值。
  🔴 必须做成可配置项（写在一个常量对象里），不许散落在代码各处。

【🔴 路况从哪来】从地图 json 每条的 **r 字段**读（0好 1普通 2差 3恶劣，不给=普通）。
  🔴 【不许自己定"商路=好、其余=普通"】—— 那是自创。
  🔴 **v0.7 实测**：r=0（好）2,886 格 · r=1（普通）35,036 格 · r=2（差）3,209 格
  🔴 **没有 r=3（恶劣）** —— 本图没有这一档，🔴 不影响（恶劣天气靠天气测，不靠路况）

【完成后应出现】
- 代码走一遍路A（好路况）和路B（差路况），分别报出：总格数 / 总体力消耗 / 实际天数
- 🔴 **判据只有两条**（Hermes Gap 2 已验证）：
   ① 两条路的【总格数】与【总点数】确实不同 —— 证明路况加成接进了消耗计算
   ② 加成能叠加（暴雨 +5 + 恶劣 +10 = 每格 30）
- 🔴 **不要验「路A 天数少但消耗高」** —— 本轮数学上不可能成立：
   只有体力池一种账时，天数 =「总点数 ÷ 每天发 50 点」，两条轴**不会反向**。
   真正的"时间换体力"取舍要等**单元 02 补给按天扣**之后才成立。
- 🔴 无论路况多差，每格都不低于基础值 15（消耗只升不降）

【AI 自检】写断言：TC-007（路况计算+叠加）、TC-011（两条路总格数/总点数确实不同）。
【进下一步的条件】路况加成确实生效（同一份代码，读 r=0 与 r=2 的格子扣的点数不同）。
【失败怎么办】如果两个数字一样 → 查路况加成有没有真的接进 `每格消耗()`。
```

## 5. 🔴 遇到问题怎么办

| 情况 | 怎么办 |
|:--|:--|
