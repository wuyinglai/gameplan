## 0. 这版为什么这么排

**核心思路跟单元 01 一样：垂直切片。** 🔴 **先串通一条最粗的完整路径（补给按天扣），再往上加。**

**为什么不按"资源→车损→士气→经济"分批做**：
那 4 块**都要经过跨日**才看得出对不对 —— 分开写，最后全在跨日那里撞车。
🔴 **现在第 ② 刀就把补给接进跨日，早暴露。**

**跟单元 01 最大的不同**：

| | 单元 01 | 🔴 单元 02 |
|:--|:--|:--|
| 代码目录 | `src/b01/` | 🔴 **`src/b02/`**（另开，不许改 b01） |
| 跨日链 | **一条**（`跨日()`） | 🔴 **两条并行**（单元01 的 + 本单元的） |
| 验收次数 | 3 次 | 🔴 **2 次**（本轮更靠后段验收） |

```
【任务】加本单元的状态字段，并实现"每天扣几份补给"的公式。

【依据】第2B类_商队生存与地点.md §3 状态 · §3.5.1/§3.5.2 数据结构 · §3.5.3 核心公式

【🔴 允许改动】只改 E:\WYY\src\b02\ 下的文件。
  🔴 不许改 src/b01/ 下任何文件（单元01 已跑通）。

【要做】
1. 建 src/b02/补给.ts
2. 在 单元01 的 游戏状态 上加 9 个字段（金币/食物/清水/零件/士气/出战人数/车损/当前地点/当前货物）
   🔴 【不要动单元01 已有的字段】：当前坐标·天数·小时·体力·天气·已到访·地图
3. 补给.ts 提供三个函数：
   应扣份数(状态) → 🔴 直接返回 状态.出战人数
   够不够(状态)   → 食物和清水是否都 >= 应扣份数
   扣(状态)       → 扣减，🔴 【扣到负数就钳到 0】

【🔴 铁律】
🔴 公式就是「应扣份数 = 出战人数」，不是「总人数 × 系数」，也不是固定 N 份。
🔴 不出战的人不消耗（"还没被雇佣"）—— 出战人数和总人数是两个字段，别搞混。

【完成后应出现】
- 🔴 出战人数=5、总人数=14 时，扣 5 份不是 14 份
- 🔴 改 出战人数=3 再调 → 扣 3 份（读的是当前值，不是缓存）
- 🔴 食物只有 2 份、出战 5 人 → 🔴 扣完变成 0 而不是 -3

【AI 自检】写断言：TC-02-001 / TC-02-002。
【进下一步的条件】上面三条都通过，且 git diff --name-only 全在 src/b02/ 下。
【失败怎么办】🔴 数字不对 → 停下报告，❌ 不许改断言迁就代码。
```

```
【任务】实现四个部位各自独立的耐久与损坏后果。

【依据】第2B类 §2.2 四部位 · §3.5.1 车损四部位类型 · 测试用例 TC-007~011

【🔴 允许改动】只改 src/b02/。

   🔴 【只有「损坏」有后果】—— 前三档纯显示，不许加任何数值惩罚
4. 损坏后果 🔴 四种各不相同：
   车轮损坏 → 【该车不能前进】
   车身损坏 → 【该车不能前进】
   车架损坏 → 【走烂路时车轮与车身磨损翻一倍】（不是不能走！）
   车篷损坏 → 【下雨时货物受损】（不是不能走！）

【🔴 铁律】
🔴 次要部位（车架/车篷）损坏，【车仍然能走】—— 不要实现成"一坏就停车"。
🔴 磨损 / 破损两档【零效果】—— 那是玩家定的设计，加了就是设计错误。

【完成后应出现】
- 晴朗+普通路走 10 格 → 🔴 只有车轮降，车身/车架/车篷【不变】
- 车轮归零 → 再走 → 【被拒绝】，体力/时间/坐标全不变
- 车架损坏 + 走烂路 → 车轮磨损【是完好的两倍】，但【还能走】
- 车轮 71% / 30% / 1% 三个档 → 每格消耗【完全一样】（因为只有损坏才有后果）

【AI 自检】写断言：TC-02-007/008/009/011。
【进下一步的条件】上面四条都过。
【失败怎么办】🔴 四部位都掉 → 做成了共用池，回去改数据结构。
```
