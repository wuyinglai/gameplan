## 🔴 为什么是这个顺序（🔴 不是随便排的）

| 排序理由 | 说明 |
|:--|:--|
| 🔴 **1.1 不碰地图** | 🔴 时间体力是纯算术，🔴 **不依赖 json**，🔴 **最容易验证** —— 🔴 失败也最容易定位 |
| 🔴 **1.2 也不碰地图** | 🔴 天气与路况只查 `状态` 与 `每格消耗()`，🔴 同样纯逻辑 |
| 🔴 **1.3 最后碰地图** | 🔴 地图是唯一要读 json 的一步，🔴 放在最后 → 🔴 **前面两步出问题不会污染它** |
| 🔴 **每步做完都能跑** | 🔴 不是「写完三个模块再串」，🔴 **是每步都有一个能跑的小闭环** |

> 🔴 **关键**：🔴 **第 2、3 步做完，第 4 步写主循环时，三个模块都已经单独测过了**
> 🔴 → 🔴 **接口对不上的问题不会攒到最后才炸。**
