> 🔴 **这是本文件的核心表。** 🔴 每个操作只出现在一个阶段里 —— 🔴 **不许两个阶段都管**。

| 操作 | 类 | 本阶段要做什么 | 备注 |

### 1.3 P3 · 事件系统

| 操作 | 类 | 归 P3 的理由 |
|:--|:-:|:--|
| 🔴 **接受事件**（触发后） | 🔴 **不是玩家按的** | 🔴 事件是**踩上去触发**，🔴 不占键位 |
| 🔴 **选事件选项** | 🔴 界面内 | 🔴 `1~4` 数字键或鼠标点 · 🔴 选项是事件的一部分 |

> 🔴 所以采集的**触发**在 P3，🔴 **给的东西**才进 P2 的资源池。
> 🔴 **这是这次分派里最容易搞错的一条。**

## §2 🔴 「跨阶段接口的操作位」是什么意思

### 2.1 P1 必须先留的空位

> 🔴 **P1 只实现旅行，但 P2~P7 的操作玩家迟早要按。**
> 🔴 **P1 要做的是「留一个明确会拒绝的位置」** —— 🔴 而不是等 P2 加。

| 空位 | P1 怎么做 | 将来谁来实现 |
|:--|:--|:--|
| 侦察 / 采集 / 搜索 | 🔴 返回失败「本阶段未实现」 | P3 / P4 |
| 补给 / 修车 / 治疗 / 招募 / 休整 | 🔴 同上 | P2 |
| 事件选项 | 🔴 同上 | P3 |
| 战斗内一切 | 🔴 同上 | P6 |
| 交易 / 接单 / 交单 / 讲价 | 🔴 同上 | P7 |

### 2.2 🔴 为什么不留到 P2 再加

| 不留的后果 | 说明 |
|:--|:--|
| 🔴 **P2 的 AI 会以为 P1 没做** | 🔴 回头补，或者两个阶段各写一半 |
| 🔴 **测试没有「拒绝」这一档** | 🔴 现在只能测「成功」和「边界失败」，🔴 测不了「功能未实现」 |
| 🔴 **接口形状会被改** | 🔴 P1 定一次形状，🔴 后面七个阶段都用它 |

> 🔴 **一句话**：🔴 **P1 定义「操作怎么被调用」，P2~P7 定义「每个操作做什么」。**

## §4 🔴 三条防打架的规矩

| # | 规矩 | 理由 |
|:-:|:--|:--|
| 1 | 🔴 **一个操作只在一个阶段里实现** | 🔴 两个阶段都做 → 🔴 改一处忘另一处 |
| 2 | 🔴 **跨阶段调用的方向是单向的** | 🔴 P2 可以调 P1 的走一格 · 🔴 P1 永远不调 P2 |
| 3 | 🔴 **键位只在一处改** | 🔴 键位权威 = `20_界面与操作.md §5` · 🔴 各阶段只引用 |
