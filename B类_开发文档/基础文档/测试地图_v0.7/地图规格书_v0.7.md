## 八、🔴 这张地图的已知偏差（🔴 别当 bug 看）

### 🔴 偏差 1 · `special` 被映射成「营地」

| 项 | 内容 |
|:--|:--|
| **现象** | 🔴 json 里 10 格 `t:'special'`，🔴 代码映射成 `'营地'` |
| **后果** | 🔴 这 10 格**会**被判成可停留营地 |
| **为什么这样** | 🔴 A 类 §4 的格子类型表里**只有「营地」，没有「探索点」** —— 🔴 改成别的就得自创类型，🔴 那是更严重的越界 |
| **处理** | 🔴 **保持现状 + 代码注释标为已知偏差** · 🔴 **等项目主裁定**「探索点要不要独立成类」 |
| **附加问题** | 🔴 这 10 格**半径 3 格内一格商路都没有** —— 🔴 玩家实际很难碰到 |

### 🔴 偏差 2 · 商路碎成 19 段（🔴 最大的问题）

| 项 | 内容 |
|:--|:--|
| **现象** | 🔴 商路 4,840 格按四方向连通算，🔴 **碎成 19 个连通分量** |
| **后果** | 🔴 **起点在分量 1（1,263 格）· 终点在分量 2（761 格）—— 两条不相连的路** |
| | 🔴 **沿商路走到终点 = 不可能** · 🔴 **沿商路能到达的地点 = 0 个** |
| **附带** | 🔴 **51 个地点半径 3 格内无商路**（城镇 14/18 不贴 · 村庄 32/41 不贴 · 营地 10/10 全不贴）· 🔴 **86 个死头商路格**（占 1.8%） |
| **根因** | 🔴 **不是"没画商路"，是"没连起来"** —— 🔴 起点/终点周围都有商路（36 格 / 11 格） |
| **待裁定** | 🔴 **跑商是「只沿商路走」还是「任何可通行格都能走」** → 决定地图改不改 |
| **完整报告** | 🔴 `其他\AI交流\地图体检报告_v0.7.md` |

> 🔴 **这条直接卡住阶段 02** —— 🔴 阶段 02 要测「进城补给」，🔴 **走不到城镇就没法测**。
> 🔴 **最晚进阶段 02 之前必须解决。**

### 🔴 偏差 3 · 原规格书的距离数据已作废

🔴 **220 / 404 / 596 格** 是旧口径（斜向或不同障碍定义）算的，🔴 **596 那个数本身也错了**。
🔴 **现以 §三 的 246 / 414 / 570 格为准** —— 🔴 **2026-10-21 用 Python 独立 BFS 复算过**
🔴 **判据**：四方向 + 🔴 **只有 `block`（山/裂谷）与 `blk_wt`（水/河）不可通行** + 未标注格按空地可通行
🔴 **与新代码 `src\p1\验收_阶段1.ts` 跑出的 570 格一致。**
