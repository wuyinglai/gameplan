# 🔴 P1 代码架构说明

> 📌 **这份是给不读代码的人看的。** 🔴 目标：看完能明白「哪个文件干什么」+「怎么自己跑」。

---

## 一、现在有什么（3 个文件）

| 文件 | 干什么 | 🔴 一句话 |
|:--|:--|:--|
| `状态.ts` | 🔴 **游戏状态的定义** | 游戏里"会变的东西"有哪些：位置、几天、几点、体力 |
| `入口.ts` | 🔴 **演示用的一步操作 + 打印** | 假装走一格，然后把结果打成人能看懂的中文 |
| `入口.test.ts` | 🔴 **验证上面两个对不对** | 5 条断言 |

> 🔴 **就这么少。** 🔴 第一阶段的任务是「把架子搭起来」，🔴 **不是把功能做完**。

---

## 二、一次操作走哪几个文件

```
   [入口.test.ts]  ← 测试：调用它，检查结果对不对
          ↓
   [入口.ts]      ← 演示：走一格 → 改状态 → 打印
          ↓ 改
   [状态.ts]      ← 状态：被改的那几个字段
```

**读法**：🔴 **箭头 = 谁调用谁。**
🔴 **「状态.ts」永远在最下面** —— 🔴 它只被动，不主动做事。

---

## 三、游戏状态里有什么、谁改它

| 字段 | 现在是什么 | 谁写它 | 谁读它 |
|:--|:--|:--|:--|
| `当前坐标` | `{ x, y }` | 🔴 入口（演示） | 入口（打印） |
| `第几天` | `1` | 🔴 还没人写（1.1 做） | 入口（打印） |
| `当前小时` | `7`（= 07:00） | 🔴 入口（演示） | 入口（打印） |
| `野外体力` | `100` | 🔴 入口（演示） | 入口（打印） |
| `体力上限` | `100` | 🔴 **没人写 —— 它是常量** | 入口（打印） |

> 🔴 **注意「体力上限」那行** —— 🔴 **没有谁写它**。🔴 这类"固定不变"的字段，
> 🔴 写代码时不会被误改，🔴 测试里专门有一条断言守着它。

## 四、🔴 怎么跑（照抄就行）

### 在 `游戏大纲\游戏本体\` 目录下：

**跑测试（会打印演示内容）**
```
npx vitest run
```

**只跑 P1**
```
npx vitest run src/p1
```

**类型检查**
```
npx tsc --noEmit
```

## 五、🔴 怎么改一行代码看到效果

| 改哪 | 改什么 | 跑什么 | 期望看到 |
|:--|:--|:--|:--|
| `状态.ts` | `野外体力: 100` → `80` | `npx vitest run` | 🔴 打印里的「体力 80 / 100」· 🔴 **测试会红**（因为断言写的是 100） |
| `入口.ts` | `状态.野外体力 -= 15` → `-= 20` | `npx vitest run` | 🔴 打印里的「体力 80 / 100」· 🔴 **测试也会红** |
| `入口.ts` | `状态.当前小时 += 2` → `+= 3` | `npx vitest run` | 🔴 打印里「09:00」→「10:00」· 🔴 **测试也红** |

> 🔴 **改完测试变红是正常的** —— 🔴 **那说明断言在守着这个地方**。
> 🔴 **这正是要的效果**：🔴 改错了会被立刻抓出来，而不是悄悄跑偏。
