# 人工测试台（浏览器 UI）· 使用说明

> 用途:让你**手动点几下**就能确认 P1 旅行逻辑和 P2 资源字段没问题。
> 🔴 这个页面**不含任何游戏规则** —— 它只调用 `src/p1`、`src/p2` 里已经写好并测过的函数,
> 所以页面显示的数字就是模块真实算出来的数字。规则要出错,锅在被调的模块,不在页面。

## 怎么起

**双击 `游戏本体\启动测试台.bat`** —— 已经在跑就只开浏览器；没在跑就启动服务并自动开浏览器；第一次会自动装依赖。

或者命令行：

```
cd C:\Users\Administrator\Desktop\游戏大纲\游戏本体
npm run ui
```

浏览器开 **http://localhost:5173**（端口被占就改 `npx vite --port 5180`）。启动用的黑窗口关掉，测试台就停了。

## 操作

| 做什么 | 怎么按 |
|:--|:--|
| 走一格 | **方向键 / WASD**（北 = y+1，原点在左下角） · 或九宫格按钮 |
| 开始下一天 | **空格** · 小按钮「结束当天」 · 绿色大按钮「⏭ 结束今天 · 开始下一天」——🔴 三个都是直接调 `结束当天()`，**任何时候点都生效**，原地连着按就连着过第 2、3、4 天 |
| 重开一局 | **R** 或「重开」 |
| **点地图走** | 点**相邻格** = 真走一格（走 `走一格()`，扣体力、推时间、按判据判定）；<br>点**远处格** = ⚠ **测试直达**（🔴 不扣体力、不推时间，只是把商队挪过去省时间，**不是游戏走法**）；点山 / 水 = 拒绝「过不去」 |
| 看附近 / 看全图 | 「视野 ±」调倍数；右边小地图永远是整张 400×400，点它也能走 / 直达 |

> 🔴 **`结束当天()` 不看体力、不看时间、也不看"今天有没有走过"**（2026-10-23 裁定后它**没有任何拒绝分支**）。
> 判据 26「开局 07:00 立刻点」和判据 27「体力 0 时点」都要求**允许**，防止把玩家锁死。
> 跨日只做四件事：天数 +1 · 时钟回 07:00 · 体力 +50（封顶 100）· 天气段 −1。

## 怎么确认「我现在是哪一格 / 我点的是哪一格」

- **当前格 = 1px 白描边 + 中心一个小白点**（🔴 小号，不挡周围格子），坐标看状态栏第三行「位置 (x, y)」
- **鼠标划过 = 橙色细框 + 坐标数字**，点下去之前就知道会命中哪一格
- **刚点过的格子 = 白色外闪细框**（0.45 秒），确认「这格我点到了」
- 🔴 商队在正中心，所以**视野里离中心 1 格以内**点下去 = 真走一格；**2 格以上** = 测试直达。
  以前没有框的时候很容易点在相邻格上，看起来就像"只能一格一格走"。
- 视野放太大或视野放太小都觉得挡？「视野 ±」调倍数：白点固定 1px 描边，不会随放大变粗

## 🔵 天气调试面板（右边那 13 个键）

天气是 **12 种按概率掷、一段持续 2~7 天、跨日时推进**（`5A §2.1 / §2.2`）：

| 天气 | 出现概率 | 一段几天 |
|:--|--:|:--|
| 晴朗 / 阴天 | 各 34% | 5~7 |
| 小雨 / 高温 / 寒潮 / 浓雾 | 各 5% | 3~6 |
| 暴雨 / 酷热 / 严寒 / 重雾 | 各 2% | 3~6 |
| 灰烬风 | 2% | 4~5 |
| 灰烬风暴 | 1% | 2~3 |

- **点哪种就强制切成哪种**（当前那种前面带 `●`）。🔴 **段长是真随机**：写 5~7 天就 5 / 6 / 7 都可能，
  不是一律取下限。做法是把剩余设成 1 去逼 `天气.推进天气段()` 重掷，只注入"第一掷必中该天气"，
  段长仍由 `天气.ts` 里的 `掷区间()` 掷 —— 页面不自己算数。
  实测点 12 次：晴朗 `{5,6,7}`、暴雨 `{3,4,5,6}`、灰烬风 `{4,5}`、灰烬风暴 `{2,3}`
- **「🎲 随机换下一段」** = 把剩余设成 1 再走**真实跨日逻辑**（`结算.跨日()` → `天气.推进天气段()`），掷出的天气名和段长都是真的
- 想连着看轮换：连按 **「⏩ 跳到明天」** 或**空格**，状态栏「还剩 N 天」会一路减到重掷

### 「随机怎么老是晴天」—— 掷 20000 次的实测分布

| 天气 | 实际 | 应有 | | 天气 | 实际 | 应有 |
|:--|--:|--:|:-|:--|--:|--:|
| 晴朗 | 33.64% | 34% | | 寒潮 | 4.95% | 5% |
| 阴天 | 34.23% | 34% | | 严寒 | 2.02% | 2% |
| 小雨 | 5.18% | 5% | | 浓雾 | 4.91% | 5% |
| 暴雨 | 2.99% | 3% | | 重雾 | 2.15% | 2% |
| 高温 | 4.96% | 5% | | 灰烬风 | 1.90% | 2% |
| 酷热 | 2.04% | 2% | | 灰烬风暴 | 1.04% | 1% |

**随机没坏，是概率本来就偏**：晴朗 + 阴天合计 **68%**，而且一段 5~7 天才换一次，
所以随手点几天大概率一直是晴天/阴天。要看特殊天气就直接点它那排按钮。

## 🟡 测试按钮（专门打边界判据）

| 按钮 | 该看到 |
|:--|:--|
| 斜着走一格 | ❌ **不是相邻格**（判据 2） |
| 隔两格走 | ❌ **不是相邻格**（判据 3） |
| 往图外走 | ❌ **出地图了**（判据 4） |
| 体力清成 0 | 再走路 ❌ **体力不够**（判据 18），时间 / 坐标不动 |
| **把时间拨到 18:00** | 再走路 ❌ **时间不够**（判据 20），**时间、体力都不动** |
| ⏩ 跳到明天 | 连推天数用（等价于「结束当天」，2026-10-23 裁定后不需要再清幂等标记） |
| P2~P7 那排虚线键 | 全部 ❌ **本阶段未实现** |

## 每走一步该看到什么

| 动作 | 期望 |
|:--|:--|
| 走一格 | 时刻 **+2 小时**、体力 **−15**、坐标变 1 格 |
| 走到 19:00 | 🔴 **就停在第 N 天 19:00**，不会自动进第二天（2026-10-23 裁定） |
| 19:00 之后再走 | ❌ 拒绝（「时间不够」，或体力先见底时报「体力不够」）· 🔴 状态一行不动 |
| 斜着走 / 隔两格 | ❌ 拒绝:**不是相邻格** |
| 往图外走 | ❌ 拒绝:**出地图了** |
| 撞山 / 撞水 | ❌ 拒绝:**过不去** |
| 体力清零后再走 | ❌ 拒绝:**体力不够** |
| 「结束当天」 | ✅ **任何时候都能点**：开局 07:00、体力满、体力 0、原地不动都行 |
| 「结束当天」连点两次 | ✅ 第一次到第 2 天、第二次到第 3 天（🔴 旧「今天已结算过了」拒绝已作废） |
| 走不动了（体力 / 时间不够） | 🔴 **时间不会自己跨日**，原地停住，绿色大按钮变**橙色**并写明「⚠ 体力不够 / ⚠ 时间不够 · 点这里开始下一天」 |
| 天气 / 路况 | 每格消耗恒 **15**（见底下第 1 条） |

> ✍️ **2026-10-23 项目主裁定**（完整留痕：`90_历史与废案\22_已落库的设计讨论记录_20261023\项目主裁定_到19点不自动跨日_20261023.md`）：
> **走路永不自动跨日**，19:00 = 今天到头、必须玩家点「结束当天」才 天数 +1 · 时钟回 07:00 · 体力 +50；
> 「结束当天」🔴 任何时候都生效（原地连着按就连着过第 2、3、4 天）。
> 依据是 A 类原文「19:00 天黑收工，天黑就得停」+「入夜睡觉不耗时间」—— 它从没说自动送第二天。
> 🔴 副作用：「时间不够」这条分支要走到 19:00 之后才撞得上，而那时往往体力也先见底（移动第 ④ 步先判体力），
> 所以想干净地测它，用「把时间拨到 18:00」这个键。

日志每行前面有**序号**,报问题时直接说「第 07 行:结束当天被拒但体力还是 70」这种,我能立刻定位。

## 三条照实说明(不算 bug,但你测试时会被绊到)

1. **天气与路况的消耗恒 15** —— `§6.1 / §6.2` 的加成数值还没裁定,两张表全 0。
   所以暴雨和晴朗走一格**都是 15**,这是当前口径,不是测坏了。
2. **起点(10,199)是大城,但脚下「已到访 = false」** —— 「走进地点格」才置 true,
   **开局就站在原地**不会触发。要不要「开局即已到访」归项目主裁定(P2 第 3 步地点服务用得上)。
3. **P2 资源永远全 0** —— 扣补给 / 断粮惩罚是第 2 步的事,现在还不动。
